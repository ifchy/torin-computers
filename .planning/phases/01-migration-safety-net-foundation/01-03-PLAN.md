Write scripts/backup-live-site.sh: it decodes the bell.host.bg Host/User/Pass from filezilla-server-data.xml at runtime (base64-decoding the Pass value) into shell variables only - never writes the decoded password to disk or prints it - then creates `backups/<UTC-timestamp>/public_html/` locally.
3. The script downloads the 16 known .html filenames and the 7 known root files (.htaccess, favicon.ico, google1718743335455f1c.html, header.js, otpuska.js, mailer.php, error_log) via curl GET requests against `ftp://bell.host.bg/public_html/<file>`, attempting `--ftp-ssl` first (per T-01-05's mitigation pattern established in plan 01-01), falling back to plain ftp:// only if TLS is rejected.
4. For the four directories (.well-known/, cgi-bin/, covid-19/, assets1/), the script enumerates each directory's entries via curl's NLST listing mode against the directory URL, recurses into any sub-entries that are themselves directories, and downloads every discovered file to the matching local relative path - bounded to whatever NLST actually reports, no fixed-depth assumption.
5. After the pull completes, the script counts the downloaded .html files (expect exactly 16) and reports the total size of the downloaded assets1/ directory, comparing it against the roughly-14MB baseline already confirmed in 01-PATTERNS.md; if the .html count is not exactly 16, or the assets1 total is well under that baseline (a strong signal of a truncated pull), the script exits non-zero with an explicit message naming which check failed, rather than reporting success.
