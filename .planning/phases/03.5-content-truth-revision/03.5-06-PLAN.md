<objective>
Finish the tree: the five component and utility pages that carry a handful of instances each, the
last five descriptions still using the old free-diagnostics wording, and the one stylesheet comment
that would otherwise fail the phase's own gate.

Two of these pages need judgement rather than deletion. `smyana-na-ekran.html` and
`ekran-klaviatura-portove.html` both carry a **diagnostic** — plug the laptop into an external
monitor; if the picture is clean there, the fault is in the screen, and if the same defect appears,
it is on the board. That diagnostic names the GPU. It promises no repair of it, it is genuinely
useful to a customer trying to describe a fault on the phone, and deleting it would cost the site a
real piece of help in order to satisfy a grep. The Class-B rule exists for exactly this case, and
this plan is where it gets applied with the most care.

`test-laptop.html` matters for a different reason: DIFF-01, the self-diagnostic tool, is now the
only original differentiator the shop still has. Its page carries a battery-regeneration line and a
link to the retired battery page. The one surviving differentiator's own page must be clean.

Why `requirements: [DIFF-04, SEO-05]`: DIFF-04 for the same reason as the other removal plans, and
SEO-05 because `test-laptop.html` is the last page linking to a retired URL.

Purpose: leave no file in the tree carrying a withdrawn claim, without deleting honest help.
Output: five corrected pages, the last five reworded descriptions, and a gate-safe stylesheet.
</objective>
