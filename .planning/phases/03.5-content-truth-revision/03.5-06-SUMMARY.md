## The ruling on the external-monitor diagnostic

**It was kept, and kept unedited.** This is the decision the plan said would need the most care,
so the reasoning is written out rather than asserted.

The block on `smyana-na-ekran.html` (lines 125-136) and its shorter twin in
`ekran-klaviatura-portove.html`'s FAQ (lines 96-97) tell a visitor how to separate two faults
using a monitor they already own: plug the laptop into it, and if the picture is clean there the
fault is in the laptop's own screen, while if the same defect appears the cause is on the board.

**Read sentence by sentence against the Class-B rule before any edit, and the measured result was
that nothing on either page needed to change.** Specifically:

- The paragraph describing what a GPU fault *looks like* is a symptom description and a diagnostic
  observation. It ends by naming the board as the cause — **and stops there.** No sentence on
  either page continues from that cause to an offer.
- «Правим тази проверка при всяко приемане, преди да ви кажем какво предстои» is a **process
  statement** about the check, not about a repair, and the plan named it explicitly as a survivor.
- The sentence warning that replacing a screen when the fault is elsewhere solves nothing and
  costs the customer for a working part is a **caution against unnecessary work** — the opposite
  of an offer.
- The `process` list and the FAQ both describe *checking* which of the two it is. Neither promises
  work on what they name.

So the plan's expectation that some sentences would have turned the diagnostic into an offer was
**not borne out by measurement.** Reported as a finding rather than acted on: nothing was rewritten
in order to have rewritten something.

**Deleting the block would have been a failure of this task, not a pass.** It is the page's actual
argument — the reason `smyana-na-ekran.html` can compete without the price it deliberately does
not publish (PRICE-01 is v2) — and it is genuinely useful to someone trying to describe a fault on
the phone. A grep reading zero would have been bought with real customer help and zero truth
gained.

**The one thing that did change on `smyana-na-ekran.html` is a comment.** The head comment quoted
the callout's heading verbatim, which put a comment-borne Class-B hit into the file's survivor
report — the file's own count disagreeing with its page copy. That is the 03-07 rule (a source
comment must never quote a string a gate greps for) reproduced exactly. The comment now describes
the block by its role, and carries the phase-3.5 ruling above so a later pass does not
re-litigate it. `$torin_desc` is unchanged at 137 code points.

## Two Class-A tokens the gate cannot see

**This is the most consequential finding in the plan, and it is a gate defect, not a page defect.**

`truth-gate.js` carries `southbridge` as the Class-A literal **«южен мост»**. Both occurrences in
this tree are in the **declined** form — «южни**я** мост» — which the literal does not match. The
gate reported **zero**, on two published instances of withdrawn vocabulary:

| File | Line (base) | Text | Disposition |
|---|---|---|---|
| `src/test-laptop.html` | 131 | «повредата почти сигурно е в южния мост на дънната платка, а не в драйверите» | corrected |
| `src/mehanichni-problemi.html` | 111 | «При USB портовете пиновете при много модели влизат директно в южния мост» | corrected |

**Both were corrected as VOCABULARY corrections, never as excisions** — the `«ниво чип»` pattern
03.5-CONTEXT establishes. In each case the surrounding claim was read first, and in each case the
claim survives:

- `test-laptop.html` — the diagnostic is *a fault that persists under Ubuntu is hardware, not
  drivers*. That survives in full; the chip name becomes the board.
- `mehanichni-problemi.html` — the claim is a **safety argument**: a wobbly USB port is not
  cosmetic because its pins land directly on a controller. A blind string-delete would have
  destroyed a live warning to satisfy a grep. The chip name becomes «управляващия чип на
  платката» — a Class-B noun inside cause prose, tabulated above.

**FINDING FOR PLAN 03.5-07 (gate, not content).** `truth-gate.js` matches Class-A literals as
plain substrings, so any Bulgarian token that inflects will be missed in its declined forms.
`«южен мост»` and `«северен мост»` are the two known-affected entries; a full audit of the
Class-A list against Bulgarian inflection belongs in the post-merge pass. **`truth-gate.js` was
NOT edited here** — it is not in this plan's `files_modified`, six plans call it, and amending the
single source from inside one wave-2 worktree is exactly how six definitions of "true" get
created. The correct fix is one audited edit in 03.5-07.

### On both reverse controls

Each asserts `rc` is **exactly 1**, never merely "did not crash". `truth-gate.js` returns 2 for a
usage error, so a mistyped path cannot be mistaken for a gate failure, and a passing run cannot be
mistaken for a silently-skipped one. The `src/css` run additionally reads the scanned-file count
back out of its own output — a swallowed directory argument scans nothing, exits 0 and prints OK,
which is indistinguishable from success.
