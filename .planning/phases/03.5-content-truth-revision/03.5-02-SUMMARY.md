**The two numbers differ by exactly one, always, and both are correct.** `torin_render_brand_row()`
is a PHP include: it emits its own band at render time and contributes no opening tag to
`index.html`. A reader who greps the source to check a rendered figure will conclude a section is
missing and add one — inventing content in the one phase that forbids it (D3.5-08).

**This is not hypothetical.** While writing the in-file note explaining exactly this trap, the note
itself wrote the opening tag out in prose and pushed the source count to 6. The Task 1 gate caught
it on the first run. The note now describes the tag rather than writing it, and says why. That is
CONTEXT's rule 6 — *a source comment must never quote verbatim a string a gate greps for* — failing
and being caught inside the file that documents it.

`adjacentTintedPairs: 0` is a property that **must hold**, not a known failure to tolerate. If a
probe ever reports non-zero, the likeliest cause is the brand row having vanished, not a tint class
being wrong: the partial emits nothing at all when its list is empty, and 03.5-01 edits exactly that
list. **Diagnose the brand list in `site-config.php` first. Do not add a section and do not change a
tint class.**

**5. [Rule 1 — Bug the plan would have introduced] Making the zero-strip case opt-in would have

- **Found during:** Task 3, while reading the verdict expression.
- **Issue:** `evidenceBoxesOk` is deliberately non-vacuous — `evidenceBoxes.length > 0 && every(…)` —
  so with zero strips it is `false`. Removing the `inconclusive` push without touching the verdict
  leaves that `false` in a conjunction, and the verdict becomes FAIL. The plan does not mention it.
  This is the second-order half of the bug the plan set out to fix, and it is invisible until a page
  is actually served.
- **Fix:** the verdict requires the box contract only where there is a box to measure
  (`!evidenceContractApplies || evidenceBoxesOk`). The excused case cannot pass silently, because
  `TRUST_EXPECT_EVIDENCE=1` sends it to INCONCLUSIVE before the verdict is reached. `evidenceBoxesOk`
  keeps its non-vacuous definition for **reporting**, so the reported value never claims a contract
  was proven when it was not.
- **Commit:** `7950a06`

**6. [Rule 2 — Missing critical functionality] A second vacuous route.**
- **Issue:** with the zero-strip case gated, a strip that IS served but contains no `img` would have
  excused the box contract with nothing reporting it — a different failure from having no strip, and
  always a defect. `[].every()` is true; this is the exact false-pass shape the file was hardened
  against.
- **Fix:** that case now pushes to `inconclusive` **unconditionally**, flag or no flag. Proven by
  control: it reports INCONCLUSIVE with the flag unset.
- **Commit:** `7950a06`

**7. [Rule 2 — Missing critical functionality] The plan requires the flag "proven in both
directions" and the only run that could do so needs a deploy the executor cannot perform.**
- **Fix:** added `scripts/trust-signals-probe-check.js`, joining the `scripts/*-check.*` convention

  the next reader would have had to rebuild it.
- **Scope note:** this file is outside the plan's `files_modified`. Recorded here rather than
  silently added.
- **Commit:** `7950a06`
