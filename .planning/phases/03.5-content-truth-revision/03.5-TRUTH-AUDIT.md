## How to read this document

Every figure below carries **the command that emitted it**, and every count carries **the token
set _and the method_ that produced it**. This is not ceremony. Three separate figures in this
phase's own records turned out to be method-dependent rather than wrong, and all three are
reconciled in this document. A count without its method is not a measurement.

Every assertion is labelled **SOURCE** or **RENDERED**. They are different domains. A grep over
`src/` says nothing about what a visitor receives, because `torin_render_evidence()` tests
`file_exists()` against the *server's* filesystem and `deploy-new.sh` uploads but never deletes —
so the live tree can differ from source **in both directions** at HTTP 200 with no error anywhere.

**A criterion with no live measurement behind it is PARTIAL, whatever the local gates said.**
Phase 3 recorded TRUST-02 as `behavior_unverified` rather than passing it, and that judgement is
the reason this phase exists in a recoverable state rather than as a post-launch discovery.

**The live sweep has now run.** Seven criteria that were PARTIAL or SOURCE-only for want of it are
resolved against measurements, and the ones the measurements do **not** settle are named with the
reason — a live figure closes a criterion only where the criterion was waiting on that figure. The
open defect is now **live-confirmed**: it is being served to visitors, not merely sitting in `src/`.

### 1. 🔴 CUTOVER-BLOCKING — the `.htaccess` retirement block, and it is now TWO edits

**If the `.htaccess` retirement block is not carried to production at the Phase 4 cutover, four of

**Missing either one breaks a redirect silently, at 301, with a `Location` header present.** That is
not hypothetical — it is exactly what this block did on its first deploy.

**Not created by this phase and not in its scope. Recorded, not fixed.** Already in STATE.md
(line 182); restated here because Phase 4's cutover reads this document.

`https://torin.bg/`, `https://www.torin.bg/`. The same content on four hosts splits ranking signals
four ways. **GSC shows the indexed, ranking variant is `http://www.torin.bg/`** (23 clicks /

`https://torin.bg/`. At cutover: pick one canonical host, 301 the other three to it, and make sure
the chosen canonical is the one GSC's history attaches to, **or the ranking history sits on a host
that now redirects away.** SEO-04 covers URL *paths*; nothing in the project covers the *host*,
which is how this went unnoticed for three phases.

### 🔧 THREE DEFECTIVE CHECK COMMANDS, found by running them

Each of the three below would have written a **FABRICATED DEFECT** into this truth audit. They are
recorded here as method findings because the central conclusion of this document is that **a figure
must be published with its method, not merely with its token set** — and these are three more
demonstrations that the method is where the error lives.

#### F11 — M4's photo regex excludes the hyphen

The plan's form is `grep -o 'img/repairs/[a-z0-9.]*'`. The character class has no `-`.

On `mehanichni-problemi` the three real files are `meh-prob2.jpg`, `meh-prob3.jpg` and
`meh-prob5.jpg`. Each **truncates at the hyphen** to the identical string `img/repairs/meh`, and
`sort -u` then collapses all three into one:

```bash
$ curl -s https://torin.bg/new/mehanichni-problemi.html | grep -o 'img/repairs/[a-z0-9.]*' | sort -u
img/repairs/meh                       # -> photos=1, against an expected 3

$ curl -s https://torin.bg/new/mehanichni-problemi.html | grep -o 'img/repairs/[a-zA-Z0-9._-]*' | sort -u
img/repairs/meh-prob2.jpg
img/repairs/meh-prob3.jpg
img/repairs/meh-prob5.jpg             # -> photos=3 ✅
```

**The page is correct. The regex is not.** The corrected form is what produced the M4 table above.
The class also gains `A-Z` for the same reason — nothing in this tree needs it today, and a filename
with a capital letter would fail the same silent way tomorrow.

#### F12 — M6's brand-row expression counts substrings, not elements

The plan's form is `grep -o 'brand-row__item' | wc -l`. It returns **8** against an expected 7,
because the closing «и др.» element carries a modifier class and therefore matches the substring
twice:

```html
<li class="brand-row__item brand-row__item--more">и др.</li>
```

```bash
$ curl -s https://torin.bg/new/index.html | grep -o 'brand-row__item' | wc -l
8                                                        # substring occurrences

$ curl -s https://torin.bg/new/index.html | grep -o '<li class="brand-row__item[^"]*"' | wc -l
7                                                        # elements ✅
```

**Element count is 7** — six manufacturer names plus the closer — and the DOM probe independently
reports `brandItemCount: 7` (M8) by counting nodes rather than text. Run as written, the check would
have reported a brand-row regression on a row that is correct.

#### F13 — the JSON-LD check parsed a multiline block line-by-line *(historical, wave 1)*

Included for completeness because it is the same class of error and completes the pattern. The
plan's JSON-LD check used a line-oriented `sed` extraction against a JSON-LD block that spans many
lines. It captured nothing and reported `Unexpected end of JSON input` — indistinguishable, in a
log, from genuinely malformed structured data.

Re-measured with a multiline parser, the block is **valid**, and carries
`sameAs: ["https://maps.google.com/?cid=7041654319750291392"]` — the verified profile URL, matching
`site-config.php:266`.

> **In this phase, the characteristic failure mode of a verification command is the FABRICATED

defect. That is the practical form of this document's rule, and it is stronger than the rule as
originally written:

> **Amended rule.** No figure may be published without its token set **and the exact command that
> produced it** — and no command may be trusted until it has been run against a case whose answer is
> known independently of the command.
