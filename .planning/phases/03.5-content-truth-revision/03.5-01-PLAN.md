<objective>
Correct the site's shared truth layer and retire the three discontinued-service URLs, proving the
whole phase's stack end-to-end before any page copy is touched.

This is the tracer. It is the thinnest slice that runs through every layer this phase modifies:
shared config data (`site-config.php`) -> shared partials (`rating-badge.php`, `brand-row.php`) ->
shared chrome that renders on all 23 pages (`header.php`, `footer.php`) -> server config
(`.htaccess`) -> the served page -> a rendered browser probe. If any of those layers is going to
break, it breaks here, after one commit, instead of after six content plans have already landed.

Two things make this slice worth spending the agent's best early-context tokens on:

1. **The rating badge's enabled path has never executed anywhere** (D3.5-07). No local PHP runtime
   exists and staging serves the disabled branch. Turning it on is the first real execution of
   `torin_render_rating_badge()`'s present state, on the homepage and on all 15 service pages at
   once.
2. **`header.php` and `footer.php` render on every one of the 23 pages.** A PHP fault introduced here
   takes down the whole tree, and HTTP 200 will not tell you — the `$torin_page` collision served 200
   on four pages while rendering the single letter «s» where prose belonged.

Purpose: make the shared layer true, and prove the deploy/verify loop works, before expansion.
Output: a corrected shared config, three live 301s, and `scripts/truth-gate.js` — the single source
of truth for the phase's forbidden-token lists, which every later plan's verify command calls
instead of re-deriving a regex. (Phase 3 re-derived a broken PHP-5.2 regex once and then inherited
it through eight plans; this file exists so that cannot happen again.)
</objective>

<environment_rules>
These bind every task in this plan. They are measured facts from Phases 1-3, not advice.

- **PHP 5.2.17.** No short array syntax, no `[]` literals, no namespaces, no closures, no
  `__DIR__`. Use `array()` and `dirname(__FILE__)`.
- **There is no local PHP interpreter.** The deploy is the only syntax and runtime check that exists.
  HTTP 200 proves nothing on its own.
- **`scripts/deploy-new.sh` is DENIED to executor subagents** by the environment permission
  classifier. Do all local work, record every live check as **NOT RUN**, never as passing, and print
  the exact deploy command for the orchestrator. Do not attempt the deploy.
- **`deploy-new.sh` with no arguments uploads all of `src/`.** Always print an explicit file list.
- **Never name a page data array `$torin_page` or any generic `$torin_*`.** `header.php` is required
  by every page and anything it assigns lands in that page's global scope.
- **A source comment must never quote verbatim a string a gate greps for.** `scripts/truth-gate.js`
  scans whole files including comments. Several comments in the files this plan touches currently
  quote forbidden literals; rewording them is part of the work, not an optional tidy-up.
- Known gate defects — substitute, never re-derive: the short-array regex
  `(=>[^;]*\]|\[\s*[^]]*=>)` fires on valid PHP 5.2 (use `(=>|=)[[:space:]]*\[|return[[:space:]]+\[`);
  BSD grep has no `-P` and mishandles `$` (use `grep -F`); zsh does not word-split unquoted
  expansions (use arrays); `grep -c` counts lines, not occurrences.
- Staging base URL is `https://torin.bg/new/`. The `/new/` segment is a Phase 4 cutover gate.
</environment_rules>

| T-03.5-01 | Tampering | `.htaccess` rewrite rules | high | mitigate | Substitution targets are developer-authored literals; no `%{HTTP_HOST}` or `%{REQUEST_URI}` reflection appears in any new rule.
