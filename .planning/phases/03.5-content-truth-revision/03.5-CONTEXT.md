## Domain

Phase 3 rebuilt the site and was live-verified: 23 pages, all HTTP 200, zero PHP warnings, SEO-01
closed, every rendered probe passing. **The work is not in question.** Between verification and now,
the shop discontinued three service lines, so parts of the site describe services that no longer
exist. This phase makes the site true again.

The cost of getting it wrong is asymmetric and real-world: a repair shop's site is read by customers
who act on it. A claim left standing is a promise the shop cannot keep; a claim cut carelessly leaves
a page with a hole where its substance used to be.

## Locked Decisions

### D3.5-01 — Three service lines are discontinued
**Source:** Owner, recorded OWNER-QUESTIONS #31.

- **Battery regeneration** — retires **DIFF-02** (was verified Complete 2026-08-26)
- **BGA / reballing / chip-level repair** — retires **DIFF-03** (was verified Complete 2026-08-26)
- **Sales line** (used laptops, spare parts) — no requirement directly

These are **retirements, not failures**. The requirements were delivered and verified; the services
went away afterwards. Any artifact describing them as "incomplete" is wrong.

### D3.5-02 — Category 4 is re-scoped, not removed
**Source:** Owner, 2026-09-11.

«Заливане и ремонт на дънни платки» keeps its place as one of the six headline categories. It now
covers:

- liquid cleaning
- corrosion removal
- **non-BGA** component-level soldering (capacitors, mosfets, fuses, connectors)
- **board replacement** where the case calls for it

Everything chip-level goes: the computer-controlled infrared BGA station, AMTECH flux, the 90%
success-rate claim, the three reballing stages, «северен мост / южен мост / видеочип».

The rewritten page must read as a complete service page — **not a page with holes where claims were
cut**. If honest content cannot fill the space, restructure the page rather than padding it.

### D3.5-03 — Retirement is by 301 redirect, never deletion
**Source:** Project convention set in OWNER-QUESTIONS #4, upheld by SEO-04's intent; requirement SEO-05.

`za-bateriite.html`, `laptopi.html` and `rezervni-chasti.html` are all among the original 16 indexed
URLs. Deleting a file 404s a URL that holds ranking history and inbound links. Each must **301 to a
relevant destination**, and no internal link may still point at them.

`covid.html` is also now cleared for retirement (owner: publicity obligation expired, only document
retention remains) — same rule applies, and OWNER-QUESTIONS #28 becomes moot if it goes.

### D3.5-04 — Category 1/2 boundary is failure type, not component
**Source:** Owner, OWNER-QUESTIONS #17.

- **Category 1** — physical and mechanical damage
- **Category 2** — malfunction or electronic fault

Stated that way it is a technician's distinction; a customer with a dark screen cannot tell which it
is. The agreed customer-facing form of the **same** boundary is the observable proxy:

- **Category 1** — «има видима повреда»
- **Category 2** — «изглежда здрав, но не работи»

Revised symptom lines:

| | |
|---|---|
| **1 · Счупвания и механични повреди** | паднал лаптоп, счупен корпус, пукнат екран, счупени панти |
| **2 · Екран, клавиатура и портове** | екранът не светва, клавиши не реагират, портът не зарежда |

**Two shipped inconsistencies this resolves:**
1. `svc-panti` is parented to `kat-2` while `kat-1`'s symptom line already claims «разхлабени панти».
2. `kat-2`'s symptom line leads with «пукнат екран», which is physical damage.

**The five child pages are COMPONENT pages and must NOT be re-parented.** A component fails both
ways — a cracked screen and a dark screen are the same repair, reached from either category.
`torin_service_href()` already routes by record, so this is a data change, not a template change.

### D3.5-05 — Brand row excludes Apple and Chromebook
**Source:** Owner, OWNER-QUESTIONS #22.

Both may still be accepted if a customer asks, but they are preferably avoided and **must not be
advertised**. `site-config.php:175` currently ships `Apple` — a live factual error on staging today.

### D3.5-06 — Warranty and free diagnostics carve out category 6
**Source:** Owner, OWNER-QUESTIONS #23 and #24.

- **Warranty:** 1 month for all repairs **except category 6** (medical and industrial equipment).
  Voided by liquid, impact, or another shop opening the device — with the owner's own caveat that
  third-party opening cannot currently be reliably detected.
- **Free diagnostics:** applies to **categories 1–5 only**. Reword to «безплатна **първоначална**
  диагностика» so it reads as a quick basic assessment, not an unlimited free investigation. This
  string ships on many pages; every instance changes.

**The 5–6 hours/day warranty clause was NOT ruled on.** `warrently.html` still reproduces it in the
shop's published wording and the source comment forbidding harmonisation stays in force. Do not touch it.

### D3.5-07 — The Google rating badge goes live
**Source:** Owner, OWNER-QUESTIONS #7; values verified live 2026-09-11.

- rating **4.7**
- review count **157** → ship as a **rounded figure with a «+»** (owner's explicit request, so the
  number stays accurate longer without a redeploy)
- profile URL **`https://maps.google.com/?cid=7041654319750291392`** (verified to resolve)

The badge is already built, wired at both consumers, and gated off behind `gbp_badge_enabled` plus an
emptiness safety net. **Its enabled render path has never executed anywhere** — no local PHP runtime
exists and staging serves the disabled branch — so enabling it is the first real execution of that
code and must be verified live, not assumed.

### D3.5-08 — Invent nothing
**Source:** Standing project rule, established for Category 6 in Phase 3 and reaffirmed here.

Where a cut leaves a page thin, **restructure honestly or record the gap against OWNER-QUESTIONS** —
never fill it with plausible-sounding replacement copy. Fabricated service claims on a repair shop's
site are a real-world harm; customers act on them. This rule outranks any page-length or word-count
target in this phase.

## Execution Constraints

1. **The live deploy is the only PHP check.** No local interpreter exists. A page returning HTTP 200
   proves nothing — the `$torin_page` collision served 200 while rendering the single letter «s»
   where prose belonged, and passed every local gate in five plans. Deploy, fetch, and grep the body
   for `<b>Warning`, `<b>Notice`, `Fatal error`, `parse error` and `<?php` leakage.
2. **`scripts/deploy-new.sh` is denied to executor subagents** by the environment permission
   classifier. Executors must record live checks as NOT RUN, never as passing, and report the exact
   deploy command; the orchestrator or user runs it.
3. **`deploy-new.sh` with no arguments uploads all of `src/`** — always pass an explicit file list.
4. **Give every page data array a page-specific name** — never a generic `$torin_*`. `header.php` is
   required by every page and anything it assigns lands in that page's global scope.
5. **An absent surface must force `INCONCLUSIVE`, never a pass** in any probe — `[].every()` is `true`.
6. **A source comment must never quote verbatim a string that a gate greps for.**
7. Known gate defects to avoid re-deriving: the short-array regex `(=>[^;]*\]|\[\s*[^]]*=>)` fires on
   valid PHP 5.2 — use `(=>|=)[[:space:]]*\[|return[[:space:]]+\[`; word-count gates count English
   comments — count only `[а-яА-Я]` tokens; BSD grep has no `-P` and mishandles `$` — use `grep -F`
   and `LC_ALL=C grep -c '[^ -~]'`; zsh does not word-split unquoted expansions — use arrays.
