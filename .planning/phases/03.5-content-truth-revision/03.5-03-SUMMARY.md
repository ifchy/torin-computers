## Deviations from Plan

**1. [Rule 3 — blocking sequencing] Task 1's `truth-gate.js` assertion could not reach exit 0
inside Task 1's own commit.** Task 1's gate asserts exit 0 over the whole file, but Task 1 was
explicitly instructed to leave `evidence` alone so that the two changes stay separately verifiable
— and the file's last remaining Class-A token (`ниво чип`) lived in the third evidence caption,
which is Task 2's slot. The two instructions cannot both hold in one commit.

Resolved by keeping the plan's task split and recording the state honestly rather than by silently
merging the tasks or by reaching into Task 2's slot early: Task 1 commits with **1 residual
Class-A hit, named in its commit message**, and Task 2's commit takes the file to **0**. Both
commits were gated; neither was recorded as passing a check it had not passed. Every other Task 1
gate (SEO, short-array, generic-global, Cyrillic count) ran and passed inside Task 1.

**2. [Rule 2 — missing content, not a plan instruction] The `fixes` list ships five entries, not
four.** S1 gives four service lines and the surviving power-circuits entry is a fifth distinct
service the owner did not re-state because it was never in question. Collapsing it into one of the
four would have string-deleted a surviving capability — the exact failure mode CONTEXT names as
blocking. The acceptance criterion is "at least four"; five entries, all traceable, satisfies it.

**3. [cosmetic] A third commit rewraps the head comment.** The Task 1 edit left an eight-word
comment line mid-sentence. No string the page renders changed; both gates re-ran at the same
results.
