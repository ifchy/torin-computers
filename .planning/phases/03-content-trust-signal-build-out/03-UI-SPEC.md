> Generated by gsd-ui-researcher, to be verified by gsd-ui-checker.
>
> **Upstream authority, in precedence order:**
> 1. `03-CONTEXT.md` (D3-01…D3-14) — LOCKED user decisions. Where anything below disagrees with
>    CONTEXT, CONTEXT wins and the disagreement is recorded in **§Conflicts & Corrections**.

### CSS budget — a measured correction to Phase 2

`02-UI-SPEC.md` states: *"Host serves **no compression** — every byte is wire cost"*, and sets
**≤ 20 KB raw total**. `src/.htaccess` repeats the claim in a comment dated 2026-08-05.

**Both are now stale.** Phase 2's own plan 02-01 added a module-guarded `mod_deflate` block, and
`02-VERIFICATION.md:287` records the live response as **`content-encoding: gzip` on CSS**. Measured
this session on the committed files:

| File | Raw | gzip -9 |
|---|---:|---:|
| `base.css` | 14,403 | 6,555 |
| `layout.css` | 3,958 | 1,677 |
| `components.css` | 28,276 | 9,901 |
| `no-js.css` | 5,280 | 2,427 |
| **Production total** | **51,917 B** | **18,302 B** |

So the shipped CSS is **2.6× over the raw budget and inside it on the wire.** The budget's *stated
reason* (no compression) no longer holds, which means the raw number was never the real constraint —
transfer size was.

**Phase 3 budget, restated on the corrected premise:**

- **Transfer ceiling: 20 KB gzipped for all production CSS.** Current headroom = **1,698 B gzipped**.
- **Phase 3 CSS delta: ≤ 4 KB raw / ≤ 1.3 KB gzipped**, across all seven surfaces combined.
  Achievable because every surface below reuses existing rules (`.section`, `.container`,
  `.eyebrow`, `.btn`, `.disc`, `.svc__process ol`) rather than defining new layout.
- If a surface cannot fit, **cut the surface, not the budget** — and say so, rather than shipping
  a 25 KB stylesheet against a 20 KB contract the way Phase 2 did without recording it.
- **Action for the executor:** correct the stale `no Content-Encoding` comment in `src/.htaccess`
  in the same change that touches that file. A comment that contradicts measured live behaviour is
  how the next phase re-derives a wrong budget.

## Spacing Scale

**Inherited verbatim from `02-UI-SPEC.md`. Phase 3 adds no token.**

| Token | Value | Phase 3 usage |
|-------|-------|---------------|
| `--sp-xs` | 4px | star-to-score gap in the rating badge |
| `--sp-sm` | 8px | brand-row row gap; breadcrumb link vertical padding; evidence caption gap |
| `--sp-md` | 16px | brand-row column gap; evidence-strip grid gap; block paragraph gap; badge inline padding |
| `--sp-lg` | 24px | callout panel padding; rating-badge top margin; warranty term→detail gap |
| `--sp-xl` | 32px | gap between stacked blocks inside the `blocks` section |
| `--sp-2xl` | 48px | unchanged (major section breaks) |
| `--sp-3xl` | 64px | unchanged |

**Non-token formulas (inherited, must not be hand-substituted):** `--container: 72rem`,
`--gutter: clamp(1rem, 4vw, 2rem)`, `--section-y: clamp(2.5rem, 6vw, 4.5rem)`, `--measure: 66ch`.

**Exceptions — 3, all inherited or derived:**

1. **44px minimum touch target** (inherited). Applies in this phase to: the rating-badge link, every
   breadcrumb link, and every link inside a `blocks` variant. `.breadcrumbs a` reaches it as
   `28px line-box + 2 × var(--sp-sm)` = **44px** exactly.
2. **`.brand-row__item` is 40px tall and is EXEMPT from the 44px floor** — it is a non-interactive
   optical box, not a control. Stated explicitly so a checker does not read it as a violation. 40 is
   a multiple of 4.
3. **Evidence photo box: 100 × 100 CSS px.** Not a spacing token — a fixed display size derived from
   the source assets (mostly 200 × 200 px), giving **2× effective density**. See §4.

## Typography

**Inherited verbatim. Exactly 4 sizes, exactly 2 weights, no fifth size, no third weight.**

| Role | Token | Size | Weight | Line height | Phase 3 applied to |
|------|-------|------|--------|-------------|--------------------|
| Display | `--fs-display` | `clamp(2.00rem, 1.55rem + 2.00vw, 3.00rem)` → 32→48px | 700 | 1.15 | **every page `<h1>`**, including the new keyword h1 (§6) |
| Heading | `--fs-heading` | `clamp(1.55rem, 1.30rem + 1.11vw, 2.05rem)` → 24.8→32.8px | 700 | 1.20 | `<h2>` on the brand row, every `blocks` variant, both DIFF sections |
| Title | `--fs-title` | `clamp(1.20rem, 1.11rem + 0.42vw, 1.40rem)` → 19.2→22.4px | 700 | 1.25 | the warranty **term** line; the rating-badge **score** |
| Body | `--fs-body` | `clamp(1.0625rem, 1.03rem + 0.15vw, 1.125rem)` → 17→18px | 400 | 1.65 | everything else — brand wordmarks, the brand disclaimer, badge label, warranty detail, block paragraphs, evidence captions, breadcrumbs |

### Rules that bind Phase 3 specifically

| Rule | Value | Why |
|---|---|---|
| **There is no `--fs-small`** | the brand-row **disclaimer renders at `--fs-body`**, differentiated only by `--c-ink-muted` | This is what makes the disclaimer read as a disclaimer rather than as fine print nobody sees. The requirement to make it visible is satisfied *structurally* by Phase 2's refusal to have a small size — do not "fix" it by adding one |
| `text-transform: uppercase` | **FORBIDDEN** — unchanged | Bulgarian uppercase Cyrillic destroys the letterforms Sofia Sans was chosen for |
| Brand names keep their own casing | `Lenovo`, `HP`, `Dell`, `Asus`, `Acer`, `Apple`, `MSI` | `HP` and `MSI` are capitalised **as trademarks**, in the mark's own form. That is not `text-transform` and must not be flagged as one. No CSS may alter brand-name casing |
| Latin subset is load-bearing here | budget both subsets (66 KB) | The brand row is Latin-only text. It is one of the concrete reasons the Latin subset is not optional (alongside `USB`, `HDMI`, `BGA`, `Viber`) |
| Measure | `--measure: 66ch` on `p`, `li` | Applies to the disclaimer, block prose and evidence captions |
| Heading wrap | `text-wrap: balance` on `h1`–`h3` | Load-bearing for the longer keyword `<h1>` (§6) |
| Letter-spacing | `normal` everywhere | unchanged |

## Component Contracts — the seven new surfaces

### 1. Brand wordmark row (TRUST-01)

> ⚠ **The orchestrator brief for this phase described a "grayscale logo strip."**
> **D3-09 rejects logo images outright** on evidence gathered from eight competitors (zero of eight
> use logo images). CONTEXT is locked and wins. See §Conflicts **C3-1** — the logo-image concerns
> (aspect normalisation, lazy-loading, CLS) are not ignored, they are *dissolved by the decision*,
> and the slot is shaped so logos can drop in later with **zero layout change**.

**Anatomy:**

```html
<section class="section brands" aria-labelledby="brands-h">
  <div class="container">
    <span class="eyebrow" aria-hidden="true"></span>
    <h2 id="brands-h">Обслужваме всички марки</h2>
    <ul class="brand-row">
      <li class="brand-row__item">Lenovo</li>
      …
      <li class="brand-row__item brand-row__item--more">и др.</li>
    </ul>
    <p class="brand-row__note">Независим извънгаранционен сервиз. Не сме оторизиран представител на нито един производител — имената на марките указват само каква техника приемаме.</p>
  </div>
</section>
```

| Contract point | Requirement |
|---|---|
| Data source | `$site['brands']`, a list in `site-config.php`, marked `[ASSUMED]` against OWNER-QUESTIONS #22. **Never hand-typed on a page.** 6–8 entries (D3-09) |
| «и др.» closer | Rendered **by the template, never stored in the data**. It is a UI affordance, not a brand |
| Layout | `display: flex; flex-wrap: wrap; gap: var(--sp-sm) var(--sp-md); list-style: none` — a *wrapping row*, not a grid. At 360px it reflows to 2–3 per line with no orphan rule needed |
| Item box | `display: inline-flex; align-items: center; min-height: 40px; padding-inline: var(--sp-md); background: var(--c-surface-2); border-radius: var(--r-md); color: var(--c-ink-deep); font-weight: var(--fw-bold); font-size: var(--fs-body)` |
| **Optical normalisation** | The `min-height: 40px` box is what makes `HP` (2 chars) and `Lenovo` (6 chars) read as *peers*. This is the wordmark equivalent of normalising logo aspect ratios — a fixed-height chip, variable width |
| «и др.» item | Same box, but `background: none; color: var(--c-ink-muted); font-weight: var(--fw-regular)` — so it reads as a continuation, not an eighth brand |
| Casing | Rendered exactly as stored. No `text-transform`, ever |
| Interactivity | **None.** Items are not links, not buttons, not hoverable. Exempt from the 44px floor |
| CLS | **Zero images ⇒ structurally zero CLS and zero lazy-loading decisions.** A direct, stated benefit of D3-09 beyond the trademark one |
| Disclaimer | `<p class="brand-row__note">` at `--fs-body` / `--c-ink-muted` / `max-width: var(--measure)` / `margin-block-start: var(--sp-md)`. **It is not optional and it is not decoration** — it is the element that converts a bare brand list into unambiguous referential use under Art. 14(1)(c) EUTMR (RESEARCH P-7). A brand row shipped without it is a contract violation |
| a11y | `aria-labelledby="brands-h"` on the section. The list is a real `<ul>` so it announces its item count |

**Placement:** homepage **and** every service page (category + child). **Not** on legal/utility pages
(`uslovia`, `warrently`, `msg`, `covid`, `laptopi`, `rezervni-chasti`) — a trademark disclaimer on a
privacy policy is noise. Rendered from **one partial**, included in two places; never duplicated markup.

**Forward-compatibility with logos (D-38 slot discipline), guaranteed structurally:**

```css
.brand-row__item > img { max-height: 24px; width: auto; display: block; }
```

Swapping the text node for `<img … height="…" width="…" loading="lazy" alt="Lenovo">` changes
nothing about row height, wrap points or section rhythm, because the item box is sized by
`min-height`, not by its contents. **If and only if logos ever ship**, the `alt` convention is the
Latin brand name alone (`alt="Lenovo"`) — never «логото на Lenovo», because the logo *is* the brand
name for a screen-reader user, and the surrounding `<h2>` already supplies the context.

### 2. Google rating badge (TRUST-02) — and its ABSENT state, specified first

> The rating value, the review count and the profile URL are **all owner-blocked**
> (OWNER-QUESTIONS #7). RESEARCH OQ-2 recommends gating render on a non-empty `gbp_url` so the badge
> **cannot ship pointing at a placeholder**. This contract adopts that, and specifies the absent case
> as the *primary* case.

#### 2a. The ABSENT state (normative)

**When `trim($site['gbp_url']) === ''` — or the rating or the count is empty — the component emits
NOTHING AT ALL.** Not a skeleton, not a placeholder, not «Очаквайте», not a greyed-out pill.

| Requirement | Detail |
|---|---|
| No layout hole | `.rating-badge` **owns its own top margin** (`margin-block-start: var(--sp-lg)`). Its parent `.cta-block` must not use `gap`, must not use `:last-child` margin resets, and **no selector may name `.rating-badge` from a parent's layout rule**. Deleting the node is therefore a *subtraction, not a redesign* — the identical structural rule Phase 2 wrote for `.cta-block__form` (`02-UI-SPEC` §4) |
| Guard | The same `torin_has_content()` discipline as every template slot: present-but-empty behaves exactly like absent (RESEARCH P-4) |
| Copy | **There is no empty-state copy for TRUST-02.** The empty state *is* the absence. Recorded here so a reviewer does not read it as an unfinished row |
| Consequence for the success criterion | Phase 3 success criterion 2 ("a visitor sees a Google rating badge") **cannot be met until #7 is answered.** That is the honest outcome, and it is preferable to shipping `4.8 от 128 отзива` as a number nobody confirmed on all 16 pages. Flag it to the owner as the single cheapest unblock in the phase |
| Verification | A checker must assert **both** paths: with `gbp_url` set the badge renders; with it empty the served HTML contains no `rating-badge` substring **and** the vertical rhythm of `.cta-block` is unchanged |

#### 2b. The PRESENT state

```html
<a class="rating-badge" href="{gbp_url}" rel="noopener">
  <svg class="rating-badge__star" aria-hidden="true" focusable="false">…</svg>
  <span class="rating-badge__score">4,8</span>
  <span class="rating-badge__label">от 128 отзива в Google</span>
</a>
```

| Contract point | Requirement |
|---|---|
| It is a **styled static link** | No embed, no iframe, no third-party script, no API call, no key. D3-07 + RESEARCH DH-1/DH-2. This phase introduces **zero secrets and zero third-party runtime code** |
| Pill | `display: inline-flex; align-items: center; gap: var(--sp-sm); min-height: 44px; padding-inline: var(--sp-md); border-radius: var(--r-md); background: var(--c-ink-deep); color: var(--c-on-dark)` |
| Score | `--fs-title`, `--fw-bold`, `--c-on-dark` |
| Label | `--fs-body`, `--fw-regular`, `--c-on-dark` |
| **Decimal separator** | **`4,8` — comma, not period.** Bulgarian decimal convention. The value is stored in `site-config.php` as the display string `'4,8'` because it is never computed with; formatting a number at render time on PHP 5.2 for one string is the wrong trade |
| Star icon | **One new icon, `star`, added to `icons.php`** (16th). Deliberate exception to the house style: it is `fill: currentColor` where every other icon is `stroke: currentColor, fill: none` — a stroked star does not read as a star at 1em. Colour `--c-brand` on the navy pill (8.39:1). `aria-hidden="true" focusable="false"`. Icon budget rises from ≤5 KB to ≤5.5 KB |
| **No `target="_blank"`** | Deliberate. It respects the visitor's own navigation choice, and it removes reverse-tabnabbing as a category rather than mitigating it. `rel="noopener"` is kept as belt-and-braces (some engines allow scripted navigation of an opener even without `target`) |
| **Link purpose (WCAG 2.4.4)** | The accessible name is the concatenation: **«4,8 от 128 отзива в Google»**. That names both the value and the destination. The score must **never** be the link's only text — a link announced as "4,8" fails 2.4.4 |
| Hover / focus | Hover `background: var(--c-ink-deep-2)` (white 8.21:1). Focus ring uses **`--c-focus`** `#0b4a9c`, **not** `--c-focus-on-dark`: `outline-offset: 2px` paints the ring on the *white page* outside the pill, where `#ffd84d` would be near-invisible. Same class of explicit call Phase 2 made for the amber button |
| Underline | None — the pill shape plus the hover state carry affordance |
| No `AggregateRating` JSON-LD | **Categorically ineligible** when a business marks up reviews of itself under `LocalBusiness`/`Organization` (RESEARCH P-1). The one permitted GBP signal is `sameAs` → the profile URL, on the existing LocalBusiness block. This is a hard prohibition, not a preference |

**Placement:** inside `.cta-block`, as the **last child**, below `.cta-block__note`. This puts the
rating exactly where the visitor is being asked to call, on the homepage **and** on every service page
(the CTA block closes the category-template spine). **One component, one surface, one variant** — the
badge is deliberately *not* placed in the hero (which already carries the amber «Безплатна
диагностика» pill; two pills above the fold is badge soup and a third amber element in one viewport).

### 3. Warranty summary (TRUST-03) — a PER-SERVICE value

**The conflict this resolves.** D3-10 says *one shared summary, never retyped per page*. RESEARCH P-6
found the site states **1 month** for services (`warrently.html:125`) and **1 year** for regenerated
batteries (`za-bateriite.html:129`). A single hardcoded string would be wrong on `za-bateriite.html`.

**Resolution — a keyed set, not a scalar.** One writer, many readers, per-service value:

```php
'warranty' => array(
  'default' => array('term' => '…', 'detail' => '…'),
  'battery' => array('term' => '…', 'detail' => '…'),
),
```

A page selects a **key** (`'warranty_key' => 'battery'`); it **never supplies a literal**. D3-10's
single-source rule is preserved exactly — the page chooses which shared fact applies, it does not
author one.

| Contract point | Requirement |
|---|---|
| Number of entries | **Exactly two**, and both trace to verbatim live-site claims. **Do not invent a third.** Whether terms genuinely vary further is OWNER-QUESTIONS #23 — every entry carries `[ASSUMED]` until answered |
| Unknown / missing key | Falls back to `default`. **Never** renders an empty «Гаранция» section (RESEARCH P-4) |
| Slot shape | The existing `$page['warranty']` slot changes from `string` to `string | array` and stays **backward compatible**: a plain string still renders as one `<p>`, so the three already-published category pages keep working unchanged. See §Conflicts C3-7 |
| Section | Reuses the existing `.svc__warranty` section, its `<h2>Гаранция</h2>` and its eyebrow. **No new section, no new heading level** |
| Term line | `<p class="svc__warranty__term">` — `--fs-title`, `--fw-bold`, `--c-ink-deep`. This is what makes the *duration* scannable without reading the paragraph |
| Detail | `<p>` — `--fs-body`, `--fw-regular`, `--c-ink`, `margin-block-start: var(--sp-lg)`, `max-width: var(--measure)` |
| Full-terms link | The slot is escaped and cannot carry an inline link. An optional `'href'` leaf renders as its own trailing `<p><a>` — the same shape as `blocks.link` (§5). Copy: «Пълни гаранционни условия» → `warrently.html` |
| Escaping | Every leaf through `torin_esc()`. No raw-HTML path is introduced anywhere in this phase |
| **The 5–6 h/day condition** | Reframed as a statement of confidence, per D3-10. **Not dropped** (it is a term the shop operates under) and **not reproduced in wording that reads as a trap.** See §Copywriting |
| Heading hierarchy | `<h2>` under the page's single `<h1>`. Flat. No `<h3>` inside the warranty block |

### 4. Differentiator feature blocks + the evidence photo strip (DIFF-01/02/03)

**DIFF-01** needs no new visual — `.selftest` shipped in Phase 2 (D-12). Phase 3 owes it real content
on `test-laptop.html` plus routing links; the *component* is done.

**DIFF-02 and DIFF-03** each get a homepage feature section: eyebrow + `<h2>` + 1–2 paragraphs of the
shop's own Bulgarian + an **evidence strip** + a link to the depth page. Both are ordinary `.section`
blocks reusing existing rules; the only new thing is the strip.

#### The evidence photo strip

RESEARCH measured the ~40 unported photographs in `site-current/assets1/img/`: **mostly 200 × 200 px**,
several 181–300, a handful larger. They are **evidence-strip scale, not hero scale** — and this
contract is built to use them credibly at their real size rather than stretch them.

```html
<ul class="evidence">
  <li><figure>
```

### 5. The structured `blocks` slot (CONTENT-01) — 3 variants, 1 tone

**Why the slot exists.** Every text slot in `torin_render_category_page()` passes through
`torin_esc()`, so **no content block can carry an inline link, an emphasis, or a second paragraph**.
Three of the phase's strongest content ideas fit no existing slot: the liquid-damage first-aid list,
the «матрица или видеочип?» diagnostic (which must link mid-thought to `test-laptop.html`), and the
«кога не си струва» honesty block (multi-paragraph prose).

**The slot is a structured sub-array, explicitly NOT a raw-HTML sink.** A `'html'` passthrough would
be the project's first unescaped output path and its first real XSS surface. Every leaf below still
goes through `torin_esc()`; the *structure*, not the string, carries the formatting.

Entry shape: `kind` · `heading` · `items` (list of strings) · optional `tone` · optional
`link` (`array('text','href')`).

| Variant | Renders | Visual contract |
|---|---|---|
| **`prose`** | `<h2>` + N `<p>` | `--fs-body`, `--c-ink`, `max-width: var(--measure)`, `margin-block-start: var(--sp-md)` between paragraphs. Multi-paragraph prose — the thing the `intro` slot structurally cannot do |
| **`steps`** | `<h2>` + `<ol>` | **Reuses `.svc__process ol` verbatim** — `display: grid; gap: var(--sp-sm); padding-inline-start: var(--sp-lg)`. No new rule, no new bullet treatment |
| **`callout`** | `<h2>` + N `<p>` in a panel | `background: var(--c-surface-2)`; `border-radius: var(--r-lg)`; `padding: var(--sp-lg)`; `border-inline-start: 3px solid var(--c-ink-deep)` — 3px matches every other keyline in the system |

| Modifier | Renders | Visual contract |
|---|---|---|
| **`tone: 'urgent'`** | applies to `callout` and `steps` | `background: var(--c-danger-surface)` `#fdecea`; `border-inline-start-color: var(--c-danger)` `#b3261e` (6.16:1, clears 1.4.11); heading **and** body in `--c-danger-ink` `#8c1d18` (7.97:1) |

**Rules that bind every variant:**

| Rule | Requirement |
|---|---|
| Heading level | Always `<h2>`, always with the existing `<span class="eyebrow" aria-hidden="true">`. **Never `<h3>`.** The page has exactly one `<h1>` and a flat row of `<h2>`s — this is what keeps the heading hierarchy valid as blocks are added and removed |
| `tone` is a styling hook only | It selects a class. It is **never interpolated into markup raw**, and it is validated against a literal whitelist before use |
| **No `role="alert"`** on the urgent variant | It is static page content, not a live region. `role="alert"` would make a screen reader interrupt on load. Stated explicitly because it is the obvious wrong move |
| Colour is not the sole carrier | The urgent block's **heading copy itself states the urgency** («…направете това веднага», «Не включвайте лаптопа»). No icon is added — there is no `alert-triangle` in `icons.php` and this phase adds exactly one icon, the star |
| `link` | Renders as its own trailing `<p><a>` at `--c-link`, `min-height: 44px` via `display: inline-block; padding-block: var(--sp-sm)` |
| Absent | `torin_has_content($page['blocks'])` — an empty list emits nothing at all |

**Position in the spine:** the whole `blocks` group renders as **one `.section`**, placed
**immediately after `svc__fixes`** and before `svc__warranty`. Rationale: the liquid-damage first-aid
block must be high on the page — a panicking visitor needs «изключете адаптера» before they need the
FAQ. Urgent content below the FAQ is a design failure. Multiple blocks stack inside the one section
with `--sp-xl` between them.

**⚠ This insertion exposes a latent defect in the shipped template — see §Conflicts C3-5.**
`section--tint` is currently **hardcoded** on specific slots (`fixes`, `process`, `related`), but
every slot is optional. A page with `fixes` but no `warranty` already renders **two adjacent tinted
bands** today. Inserting `blocks` makes this worse, not new.

**Contract: the template maintains a running tint toggle**, PHP 5.2-safe — one boolean flipped once
per *emitted* section, so alternation is correct for every combination of present slots, including
zero blocks, and including the homepage's newly inserted sections. Hardcoded `section--tint` literals
must be removed from the template in the same change.

### 6. Per-page `<h1>` (SEO-01 / D3-14)

**The collision.** `category-page.php:114` emits `<h1><?php echo torin_esc($cat['name']); ?></h1>` —
deliberately, so a D-40 rename cannot strand a stale heading. D3-14 requires *"one `<h1>` with primary
keyword + «София» where it reads naturally"*. «Оптимизация» is 11 characters and contains neither.

**Resolution — RESEARCH Pattern 1, option 1:** an **optional `$page['h1']`**, defaulting to
`$cat['name']`. The guarantee is preserved for any page that does not set it; the override is visible
in exactly one place per page. **This decision must land before any page copy is authored** (RESEARCH
P-3) — it changes what sixteen `<h1>`s say.

| Contract point | Requirement |
|---|---|
| Typography | `--fs-display` (32 → 48px), `--fw-bold` 700, line-height **1.15**, `text-wrap: balance`. Same as every other page `<h1>` — no special case |
| **Length cap: ≤ 48 characters** | Measured: at 360px the content box is 328px (`--gutter` clamps to its 1rem floor); Sofia Sans Cyrillic averages ~0.56em → ~17.9px/char at 32px → **~18 chars/line**. 48 chars = **3 lines = 110px**. That is the ceiling at which a category `<h1>` does not push its intro paragraph off a 640px-tall screen |
| Mobile behaviour | Wraps to at most 3 lines; `text-wrap: balance` prevents a one-word last line. **Never truncated, never `text-overflow: ellipsis`, never a smaller size at mobile** — the `clamp()` already handles the size and a fifth type size is forbidden |
| Category pages have no hero | So a longer `<h1>` cannot "wreck the hero" — it can only push the intro down, which the 48-char cap bounds. The **homepage** `<h1>` stays in the hero, unchanged: «Ремонт на лаптопи и компютри в София» (36 ch) already satisfies keyword + «София» |
| Empty guard | An override that is present-but-empty falls back to `$cat['name']`. An empty `<h1>` must never render |
| `<h1>` ≠ `<title>` | Three category pages currently derive `$torin_title` from the record. Decoupling them is a prerequisite for keyword-first titles — and the `<h1>` must not be the only place «София» appears |
| Exactly one `<h1>` per page | Unchanged, and now genuinely at risk as blocks are added. Every `blocks` variant emits `<h2>`; nothing in this phase may emit a second `<h1>` |

Introduced by the five-child split, and the carrier of the **one schema addition that earns a Google

| Contract point | Requirement |
|---|---|
| Position | Inside the first `.svc` section, **above the `<h1>`**, `margin-block-end: var(--sp-md)` |
| Where it appears | Child pages and category pages that have a parent hub. **Never on the homepage.** Max depth **3** |
| Typography | `--fs-body`, `--c-ink-muted`; links `--c-link` (8.49:1); current page `--c-ink`, not a link |

## Conflicts & Corrections

> Where a UI decision conflicts with the orchestrator brief, a CONTEXT decision, a Phase 2 contract
> or a research finding, it is flagged here rather than silently resolved.

### C3-1 — ⚠ The orchestrator brief's "grayscale logo strip" is overridden by D3-09

The brief for this phase specified a grayscale **logo** row and asked for logo sizing, optical
normalisation across aspect ratios, lazy-loading and CLS handling, and an `alt`-text convention.
**D3-09 is a locked CONTEXT decision that rejects logo images**, on evidence gathered live across
eight competitors: **zero of eight use logo images**; several position explicitly as
«извънгаранционен сервиз»; the longest lists (47, 80+ brands) read as keyword stuffing; and the
market's most modern competitor omits brands entirely.

**Resolution:** text wordmarks. The brief's concerns are not dropped, they are *answered in the
wordmark idiom* (§1): optical normalisation becomes a fixed-height chip; CLS becomes structurally
zero because there are no images; lazy-loading becomes a non-question; the `alt` convention is
specified anyway, as the forward-compatible path. The trademark point the brief raised is the one
that survives fully — and it lands on the **disclaimer sentence**, which this contract makes
mandatory rather than optional.

### C3-2 — Correction to `02-UI-SPEC` and to `src/.htaccess`: gzip is live

`02-UI-SPEC` asserts *"Host serves no compression — every byte is wire cost"* and sets ≤ 20 KB raw.
`src/.htaccess` repeats it in a comment dated 2026-08-05. **`02-VERIFICATION.md:287` records
`content-encoding: gzip` on CSS from the live origin**, because Phase 2's own plan 02-01 added the
`mod_deflate` block *after* that comment was written.

Measured: **51,917 B raw → 18,302 B gzipped.** The shipped CSS is 2.6× over the raw budget and inside
it on the wire. Phase 3 therefore budgets **transfer, not raw** (≤ 20 KB gzipped total; ≤ 1.3 KB
gzipped delta for all seven surfaces). The stale `.htaccess` comment should be corrected in the same
change that touches that file — a comment contradicting measured live behaviour is how the next phase
re-derives a wrong constraint.

### C3-3 — The accent reserved-list grows from 6 elements to 7

The rating badge's star is a new amber use. `--c-brand` on `--c-ink-deep` computes **8.39:1**. It is
decorative, `aria-hidden`, and never the sole carrier of meaning. Recorded rather than absorbed,
because `02-UI-SPEC` says *"exactly these 6 elements, nothing else"* and a checker measuring against
that list would otherwise flag it. **Per-viewport amber budget is unchanged**: the badge sits in the
CTA block alongside two amber buttons, and one small star fill does not constitute a third fill.

### C3-4 — `--c-danger*` scope extended beyond form validation

`02-UI-SPEC` declares the danger triple exists *"solely for the Phase 4 contact form"*. This phase
uses it for the `tone: urgent` content callout (the liquid-damage first-aid block). Justification:
«Не включвайте лаптопа» is a genuine urgency signal and is exactly what that colour family
communicates; the alternative is inventing a fourth semantic colour triple for one block, which
would be three new tokens against a system that declares its token count as a tripwire.
No new token is added.

### C3-5 — Latent defect in the shipped template: `section--tint` is hardcoded on optional slots

`category-page.php` hardcodes `section--tint` on `fixes`, `process` and `related`, but **every slot is
optional**. A page with `fixes` and no `warranty` already renders two adjacent tinted bands today —
this is a live defect, not one Phase 3 creates. Inserting `blocks` makes it more likely to be seen.
**Fix is contracted in §5:** a running tint toggle flipped once per emitted section, with the
hardcoded literals removed. Cheap, PHP 5.2-safe, and it makes the alternation correct for every
combination of present slots including the ones nobody has written yet.

### C3-6 — Knowing, bounded departure from D3-14's photo deferral

D3-14 defers *"2–3 real repair photos"* to a v2 checklist on the strength of OWNER-QUESTIONS #12/#13.
Those questions ask for **new** photography; RESEARCH found ~40 photographs **already in the
repository**, never ported. This contract re-admits them at **≤ 3 per page, at evidence scale only**
(§4). The deferral's premise — "we have no photos" — is factually wrong; its conclusion for *new*
photography is untouched. A page about board-level repair that shows three photographs of board-level
repair is a materially different page.

### C3-7 — The `warranty` slot changes shape (back-compatibly)

`string` → `string | array('term','detail'[,'href'])`. A plain string still renders as one `<p>`, so
the three published category pages keep working with no edit. This is the minimum change that lets
TRUST-03 carry a **per-service** value (1 month for repairs, 1 year for regenerated batteries) while
keeping D3-10's single-writer rule intact — the page selects a **key**, it never authors a literal.

### C3-8 — Three template changes must land before any page copy is authored

The `h1` override (§6), the `blocks` slot (§5) and the `warranty` shape (§3) are **structural, not
editorial**, and all three change what sixteen pages say. RESEARCH P-3's warning sign is *"a plan
that authors category-page copy without having touched `category-page.php`."* Sequence them first.

### C3-9 — Server-side omission that lands with the photos

`src/.htaccess` declares `ExpiresByType` for `image/png` and `image/svg+xml` but **not
`image/jpeg`**. Every ported photograph falls to undeclared heuristic caching. One line, same change.
