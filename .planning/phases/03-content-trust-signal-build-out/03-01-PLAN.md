<objective>
Build the content machine this phase pours 23 pages through, and prove it end-to-end on one real
page before any other page copy is authored.

Phase 2 shipped an eight-slot category template whose every text slot escapes. Three structural
collisions block Phase 3 from using it: the `<h1>` is hardwired to the category record name and
therefore carries no keyword and no «София» (RESEARCH Pattern 1 / P-3); no slot can hold a
multi-paragraph passage, an ordered urgent list, or a mid-sentence link (RESEARCH Pattern 2); and
the warranty slot is a scalar, so one shared string would be wrong on the battery page (RESEARCH
P-6). A fourth is latent: `section--tint` is hardcoded on three optional slots, so a page that
fills some and not others already renders two adjacent tinted bands (UI-SPEC C3-5).

All four are resolved here, in one pass, before any page is written — UI-SPEC C3-8 and RESEARCH
P-3 both name "a plan that authors category-page copy without having touched `category-page.php`"
as the failure mode. The proof is `zalivane-technosti.html` (category 4) authored to the full
D3-14 Definition of Done and verified in the served response on the live staging host.

Purpose: every later plan in this phase is a content plan running on a machine that already works.
Output: extended template + config + child-record data file + BreadcrumbList emitter + CSS, and
one finished category page.
</objective>

<assumption_delta_decision>
**Noun now primary:** the **service page**. A *category* page is the variant of a service page that
carries a `cat_id`; the five D3-03 child pages are the variant that does not.

**Decision: promote.** `torin_render_category_page()` is generalized into
`torin_render_service_page()` and the old name is kept only as a one-line back-compat alias. The
alternative — adding a second, parallel renderer alongside the still-required category one — was
rejected: two renderers means every later slot change lands twice, and RESEARCH P-5 records the
concrete failure it invites (a child page reaching for the category renderer resolves no record,
returns early, and serves a full header and footer with literally nothing between them at HTTP 200
— exactly the thin-content shape the D-23 publish gate exists to prevent).

**What would force a later revisit:** a child page that needs a section the category spine does not
have. None of the five in D3-03 does.
</assumption_delta_decision>

**2. `src/includes/category-page.php` — five changes, all as additional instances of patterns
already in the file.**

(a) **Generalize the renderer.** Add `torin_render_service_page($page)`. `cat_id` becomes optional:
when present, the record is looked up as today and supplies the display name and symptom line; when
absent, `$page['name']` supplies the display name and `$page['symptoms']` the optional symptom line.
An absent-or-unresolvable `cat_id` with no `name` still returns early — but add a
`trigger_error(..., E_USER_NOTICE)`-free guard comment recording RESEARCH P-5: the silent early
return is what would serve a header, a footer and nothing between them at HTTP 200. Keep
`torin_render_category_page($page)` as a one-line alias that calls the new function, with a comment
saying it exists so no already-published page breaks mid-phase.

(b) **`h1` override.** `$page['h1']` overrides the heading; present-but-empty falls back to the
record name via `torin_has_content()`. Add the guard to the guard-declaration block, not inline. The
comment must state why the default exists (a D-40 rename must not strand a stale heading) so the
override reads as opt-in rather than as the rule being abandoned.

(c) **Structured `blocks` slot.** `$page['blocks']` is a list of entries carrying `kind`, `heading`,
`items` (a list of strings), optional `tone` and optional `link` (`array('text','href')`). Render
the whole group as ONE `<section class="section svc__blocks">` placed immediately after
`svc__fixes` and before `svc__warranty`. Validate `kind` against the literal whitelist `prose`,
`steps`, `callout` and `tone` against the literal whitelist `urgent`, both the way `icons.php`
handles an unknown icon name — skip silently, never render half-formed markup (UI-SPEC §5 `error`
and `partial`). `steps` emits `<ol>` reusing the existing `.svc__process ol` rule; `prose` and
`callout` emit one `<p>` per item. Each entry's `<h2>` is preceded by the existing
`<span class="eyebrow" aria-hidden="true">`; never an `<h3>`. `link` renders as its own trailing
`<p><a>`. Every leaf goes through `torin_esc()`; the class name for `tone` is selected from the
whitelist and never interpolated from the data.

(d) **Warranty becomes a keyed lookup, back-compatibly.** `$page['warranty_key']` selects an entry
from `$site['warranty']`, defaulting to `'default'` when absent or unknown. A legacy scalar

The rendered block is a `<p class="svc__warranty__term">` carrying the term, then the detail `<p>`,

existing `.svc__warranty` section and its `<h2>Гаранция</h2>` — no new section, no new heading level.

(e) **Breadcrumbs and the running tint toggle.** Add `torin_render_breadcrumbs($crumbs)` rendering
