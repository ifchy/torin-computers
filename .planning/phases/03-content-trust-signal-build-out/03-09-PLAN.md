<objective>
Close SEO-01 across the whole tree, which is the one thing no earlier plan in this phase could do.

Every plan from 03-01 through 03-08 wrote metadata for the pages it authored, and every one of them
could only assert uniqueness, ordering and non-emptiness inside its own two-to-six-page slice. Five of
them said so explicitly and named this plan as the owner of the site-wide assertion. That assertion is
the actual requirement: SEO-01 reads *unique per page*, and uniqueness is not a property any subset
can hold.

Three things fall out of running last. RESEARCH §SEO Metadata Architecture recommends the metadata
pass happen against finished body copy rather than ahead of it, which is only now true. The all-caps
brand suffix measured at 228 px — 38% of the entire desktop title budget — is replaced everywhere by
the short form, and this is the first moment every title exists to replace it on. And `src/index.html`
is the one page in the tree that no plan claimed for SEO-01: its Phase 2 title is the legacy all-caps
sentence and its Phase 2 description was written before a single word of the new copy existed.

The gate this plan builds is a script rather than a grep, for one specific reason. All 23 titles and
descriptions are Cyrillic, and UTF-8 encodes Cyrillic at two bytes per character. A shell length check
reads a correct 129-character description as 230 and rejects it. Deciding *whose definition of length
applies* is not a formality here — it is the difference between a gate that measures the copy and a
gate that measures the encoding.

Purpose: phase success criterion 6, as a property of the site rather than of any page.
Output: one reusable gate, the homepage's metadata, and a tree that passes.
</objective>

**2. Create `scripts/seo-metadata-check.js`.** A Node script, no dependencies, exit 0 when every rule
passes and exit 1 with a readable per-page per-rule failure table otherwise. Two modes: the default
source mode reads the repository, and `--live` additionally fetches each page as served and checks the
served values too. Live mode shells out to `curl -sS --fail`, matching every other live check in this
phase. Every URL it touches is public, so it must never open the FTP credential file at the repo root,
never build a curl auth file, and never pass authentication flags to curl — and it must not name any
of those mechanisms in a comment either, because Task 1's gate greps this file for exactly those
tokens and a well-meant explanatory comment would fail it.

**The encoding contract — state it as a comment block at the top of the file, because it is the
decision the whole script rests on.** Length is measured in **Unicode code points on an NFC-normalised
string**. Not bytes: UTF-8 encodes Cyrillic at two bytes per character, so a byte count reads a correct
129-character description as 230 and rejects it. Not UTF-16 units either, though for this content the
two coincide — the script asserts that they coincide rather than assuming it. Bulgarian uses no
combining marks, so code points and grapheme clusters are the same thing for every string in this
tree, and the script asserts that too rather than trusting it. The only length expression permitted
anywhere in the file is the spread-then-`.length` form; a byte-length property, a byte-mode character
count and a non-multibyte string-length call are each forbidden, and Task 3 greps for them.

**Two exemption constants at the top, each with its rationale inline**, so widening one is a visible
reviewed diff rather than a silent pass:

- `EXEMPTIONS` — pages exempt from the 120-140 description budget. Exactly one entry: `msg.html`,
  the post-submission confirmation page, which plan 03-06 deliberately gave a short plain description
  because it has no search intent and is reached only after a form POST. Its floor is 60 code points;
  it is exempt from the ceiling on nothing.
- `LONG_SUFFIX_OK` — pages permitted the longer two-word brand suffix rather than the short one.
  Exactly two entries: `warrently.html` and `covid.html`, both documents where the full registered
  form of the company name is the appropriate register. A third entry is a review question.

Plus `BRAND_IS_SUBJECT`, one entry: `about.html`, the page whose subject is the company, and therefore
the one page whose title may contain the company name outside the suffix.

**Every run prints its three lists back, sorted, one per line**, in the form `exemptions:` then a
space-separated sorted list, and likewise `long-suffix:` and `brand-is-subject:`. This is what lets a
later gate assert the lists were not widened, by reading them out of a run rather than by pattern-
matching source code that may legitimately mention a filename for other reasons.

**Rules, each named so a failure report reads as a rule name plus a page name.** For every page:

- `literal` — the file contains a `$torin_title` and a `$torin_desc` assignment whose right-hand side
  is a single-quoted PHP string on one line, with no concatenation and no variable. A title derived
  from a record is exactly what plan 03-08 converted to literals, and this rule is what keeps it
  converted.
- `assigned-before-include` — both assignments appear at a lower line number than the `header.php`
  include in the same file.
- `nonempty` — both values are non-empty after trimming.
- `not-fallback` — neither value equals either of the two fallback defaults, whose literals the script
  extracts from `src/includes/header.php` at runtime. This is the sharpest available form of the empty
  case: on this site an "empty" title is not a blank string, it is a page that silently inherits the
  site default and therefore reads identically to fifteen others.
- `nfc` — each value equals its own NFC normalisation and contains no code point in the combining
  diacritical range, which is what makes the code-point count equal to the grapheme count.
- `bmp-only` — each value's code-point count equals its UTF-16 unit count, so no astral character can
  make the two definitions of length disagree.
- `no-mixed-script` — no maximal run of letters within either value contains both a Cyrillic and a
  Latin letter. Whole Latin tokens are fine and expected: `USB`, `HDMI`, and the operational programme
  reference on the funding-disclosure page. A Latin character *inside* a Cyrillic word is a homoglyph
  typo that defeats every uniqueness check downstream.
- `title-len` — at most 55 code points.
- `desc-len` — 120 to 140 code points, subject to `EXEMPTIONS`.
- `cta-position` — the description contains one of a small set of call-to-action verb forms and its
  code-point index is below 95, so the call survives mobile truncation. Pages whose description is
  legitimately non-commercial (the ones in `EXEMPTIONS`, plus the two documents in `LONG_SUFFIX_OK`)
  are reported as `cta-position: n/a` rather than failing — this rule must state which pages it
  skipped, never skip silently.
- `suffix` — the final separator-delimited segment of the title is exactly the short brand form, or
  the two-word form on a page listed in `LONG_SUFFIX_OK`.
- `no-legacy-suffix` — the title does not contain the all-caps brand form as its suffix segment.
- `keyword-first` — the title does not begin with the brand in any case form, and, except for the page
  in `BRAND_IS_SUBJECT`, contains the brand only in the suffix segment.
- `title-matches-page` — the title's leading segment shares at least one token of five or more letters
  with that page's `<h1>` text, compared case-insensitively after NFC. Resolve the `<h1>` from the
  served HTML in live mode and from the page's `h1` data key or literal `<h1>` element in source mode;
  if it cannot be resolved, report `unresolved` and **fail** rather than pass. This is the rule that
  catches a title describing a different page than the one it labels.

And across the set:

- `unique-title` and `unique-desc` — pairwise distinct after NFC, lowercasing and whitespace
  collapsing. Normalising before comparing is the encoding decision doing real work: two strings that
  differ only in normalisation form are identical to a searcher and distinct to a naive comparison.
- `distinct-lead` — no two titles share a normalised leading segment. This is the adjacency case the
  five category-2 siblings create: five pages that differ only in their suffix would each be unique by
  string equality and interchangeable in a result list.
- `distinct-desc-head` — no two descriptions share their first 60 normalised code points.

In live mode, additionally: fetch each page, extract the `<title>` text and the description `content`
attribute, HTML-decode both (header.php escapes with the quote-inclusive flag, so an apostrophe
arrives as a numeric entity), assert each served value equals its source literal, and run the
whole rule set again over the served values. A served value that disagrees with its source literal
means the escaping or the assignment ordering broke, which is the one failure mode a source-only check
cannot see.
