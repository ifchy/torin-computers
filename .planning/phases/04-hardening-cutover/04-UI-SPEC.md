# Phase 4 — UI Design Contract

> Visual and interaction contract for Phase 4 (Hardening & Cutover).
> Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> **Upstream authority:** `04-CONTEXT.md` (D4-01…D4-34) is canonical and LOCKED.
> `02-UI-SPEC.md` is the **inherited design system** and is equally binding — Phase 4
> REUSES it and may not invent a token, a size, a weight or a colour role. This document
> declares only the **delta**: the new surfaces, the states they need, the copy they carry,
> and the three places where a locked decision or a research claim does not survive
> measurement (**§Conflicts & Corrections**).
>
> **Everything visitor-facing is Bulgarian.** English exists only in code comments.
>
> **All numbers in this document were measured, not estimated.** Advance widths were
> computed from the shipped `src/fonts/sofia-sans-*.woff2` at the shipped weights (method
> validated: it reproduces `components.css:386`'s own «Пишете във Viber» = 141px figure to
> 0.2px). Contrast ratios were computed from the sRGB relative-luminance formula. Wire
> sizes were fetched from `https://torin.bg/new/` on 2026-09-17.

## Spacing Scale

**Inherited verbatim. No new token. Every value below already exists in `base.css`.**

| Token | Value | Phase-4 usage |
|-------|-------|---------------|
| `--sp-xs` | 4px | label → input gap; input → helper/error gap; required-marker offset |
| `--sp-sm` | 8px | icon → label gap inside `.btn`; banner icon gap; file-row gap |
| `--sp-md` | 16px | input inline padding; banner block padding; `.notice` padding |
| `--sp-lg` | 24px | **gap between form fields**; `.btn` inline padding |
| `--sp-xl` | 32px | fieldset → fieldset; form → contact-details block |
| `--sp-2xl` | 48px | contact-page section breaks (inherited `--section-y` floor also applies) |
| `--sp-3xl` | 64px | unused in Phase 4 |

### Exceptions — 4 total, all justified, all multiples of 4 or declared formulas

1. **44 × 44 px minimum hit area** (inherited). Applies newly to: the consent checkbox row,
   the `::file-selector-button`, each per-file remove button, and each breadcrumb link.
2. **48 px control height** (inherited from `.btn`). Every text input and `<select>` matches
   the button height exactly, so a field and a button on the same row never disagree.
3. **`textarea` min-height: 8rem (128px)** — ≈5 rows at `--fs-body`/1.65. A 3-row textarea
   invites a one-line answer, and the fault description is the field the owner actually
   needs prose in.
4. **`--form-measure: 34rem` (544px)** — a formula-class value in the same family as
   `--container` / `--gutter` / `--measure`, **not** a scale step and never to be
   hand-substituted. Rationale: `--measure: 66ch` is a reading measure and is far too wide
   for a single-column form; 34rem keeps the label→input→error relationship scannable and
   keeps the eye from travelling across an empty input. Declared once in `base.css`
   alongside the other three formulas.

No other value may appear in a `margin`, `padding` or `gap` declaration.

## Typography

**Inherited verbatim: exactly 4 sizes, exactly 2 weights, no fifth size, no `--fs-small`.**

| Role | Token | Weight | Line height | Phase-4 application |
|---|---|---|---|---|
| Display | `--fs-display` | 700 | 1.15 | `kontakti.html` `h1` «Контакти», `msg.html` `h1` |
| Heading | `--fs-heading` | 700 | 1.20 | `h2` «Изпратете запитване», `h2` «Къде да ни намерите» |
| Title | `--fs-title` | 700 | 1.25 | `.notice` heading inside the error summary; contact-details column heads |
| Body | `--fs-body` | 400 | 1.65 | **everything else** — field labels, helper text, error text, consent sentence, banner text, legend, file names |

### Form-specific typography rules

| Rule | Value | Why |
|---|---|---|
| Field label | `--fs-body` / **700** | Bold is the only differentiator available (there is no medium weight and no small size). It is enough: a bold label over a 48px filled input reads unambiguously as a label |
| Helper text | `--fs-body` / 400 / `--c-ink-muted` | **Differentiated by colour, never by size** — the Phase-2 C-2 rule. Sofia Sans's x-height is 488/1000; a 15px helper line would read like ~13.4px of Inter to a mobile-heavy, non-young Bulgarian audience |
| Error text | `--fs-body` / 400 / `--c-danger` **+ the `alert` icon** | Never colour alone (WCAG 1.4.1) |
| Input value text | `--fs-body` / 400 / `--c-ink` | Inputs inherit `font: inherit` from the `base.css` reset — already correct, do not restate |
| `letter-spacing` | `normal` everywhere | Latin-tuned tracking damages Cyrillic rhythm |
| `text-transform: uppercase` | **forbidden**, including on labels and the submit button | Bulgarian uppercase Cyrillic destroys the letterforms Sofia Sans was chosen for, and lengthens already-long strings |
| **Placeholders** | **forbidden outright in this phase** | A placeholder is not a label; it vanishes on focus, fails low-vision users, and on a form whose whole job is a careful fault description it is the wrong affordance. Every hint that would have been a placeholder is helper text under the input instead. `--c-ink-muted`'s Phase-2 "placeholders" role is therefore **unused** in Phase 4 — that is deliberate, not an omission |

## Component Contracts

### C-1 — Holiday banner (`.holiday-banner`) · D4-27, OWNER-02

**Placement:** the **first child of `#wrap`**, immediately before `<header class="site-header">`,
rendered by `includes/banner.php` and called from `header.php` **once**. Every page gets it or
no page does.

**Not sticky.** A non-dismissible strip that is also `position: fixed` is a permanent tax on
the mobile viewport and would fight D-30's above-the-fold arithmetic on every page forever.
It scrolls away with the page. A visitor landing on any page sees it at the top, which is the
requirement.

**Not dismissible** (D4-27). Therefore: **no close button, no `localStorage`, no JavaScript at
all.** The banner's entire cost is markup + CSS.

```html
<div class="holiday-banner">
  <div class="container holiday-banner__inner">
    <!-- torin_icon('clock') — decorative, aria-hidden -->
    <p><strong>Затворено: 10 – 20 август 2026.</strong> Сервизът е в годишен отпуск. Приемаме заявки по телефона.</p>
  </div>
</div>
```

| Property | Value |
|---|---|
| Fill | `--c-ink-deepest` `#0a2547` |
| Text | `--c-on-dark` `#ffffff`, `--fs-body`/400/1.65 |
| Date prefix | `<strong>` → `--fw-bold`, same white (15.35:1). **Not** `--c-on-dark-muted` — the dates are the most load-bearing part |
| Keyline | `box-shadow: inset 0 -3px 0 var(--c-brand)` — **bottom** edge, inset, never a `border` |
| Layout | `.container` + `display: grid; grid-template-columns: 1.25em 1fr; gap: var(--sp-sm); align-items: start` — the same three declarations `.notice` already uses, so the icon column cannot drift |
| Padding | `padding-block: var(--sp-md)` |
| `p` max-width | `max-width: none` — the `base.css` `p { max-width: 66ch }` rule would otherwise narrow the strip on desktop and make it read like body copy |
| Semantics | a plain `<div>` + `<p>`. **`role="alert"` and `role="status"` are both FORBIDDEN** — this is static content present at first paint, not a live update; either role makes a screen reader interrupt itself on every one of 20 pages |
| Links | none. If the owner's message needs a link, that is a future decision — the settings value is escaped text and must stay escaped text (`torin_esc`), not an HTML sink |

**Visibility rule (D4-27):** rendered **only** when `vacation_from` and `vacation_to` both
parse as ISO dates **and** `date('Y-m-d') <= vacation_to`, evaluated with
`date_default_timezone_set('Europe/Sofia')`. Empty `vacation_from` = off, and off is the
shipped default. Auto-expiry is therefore a property of the render, not a thing the owner
switches — which is what OWNER-02 asks for.

**Date rendering:** `10 – 20 август 2026` — an en dash with spaces, matching
`site-config.php`'s existing `'Понеделник – Петък, 8:00 – 16:00'`. PHP 5.2 on this host has
no reliable Bulgarian locale, so `includes/settings.php` carries a **12-entry Bulgarian month
array** and formats the string itself. Same month → one month name («10 – 20 август 2026»);
different months → both («28 декември 2026 – 5 януари 2027»).

#### The measured cost, stated rather than glossed

Phase 2's D-30 arithmetic puts the homepage's first category card's bottom edge at **574.8px**
against **584px** of usable mobile viewport at 360 × 640 — **9.2px of margin**. Any banner at
all consumes it.

Measured at 360px (content box 328px, icon column 21.3px + 8px gap → 298.7px of text column,
`--fs-body` 17.02px at line-height 1.65 = 28.1px per line, plus 32px of block padding):

| Message length | Lines (incl. date prefix) | Banner height | Card-1 bottom |
|---|---:|---:|---:|
| 57 cp (the shipped default) + 31 cp prefix | 3 | **116px** | 691px — below the fold |
| 90 cp | 4 | 144px | 719px |
| 120 cp (**the cap this contract sets**) | 5 | 172px | 747px |
| 300 cp (research's `strlen` cap) | 10 | 313px | 888px |

**Resolution — accepted, with a cap.** When the shop is closed, the closure *is* the most
important thing on the page and it outranks the fold contract; D-30 is knowingly suspended
for the duration. But 300 characters is not a banner, it is a paragraph, so:

- `vacation_message` is capped at **120 code points**, not 300 bytes.
- **The cap must be counted in code points, not bytes.** `strlen($val) <= 300` in
  `04-RESEARCH.md` C-5 counts *bytes*; Cyrillic is 2 bytes per character in UTF-8, so that
  expression permits 150 characters, not 300, and permits 300 if the owner happens to type
  Latin. Use `mb_strlen($val, 'UTF-8')`, or the 5.2-safe
  `preg_match_all('/./u', $val, $m)` count if `mbstring` is not confirmed present by the
  D4-06 probe.
- The Bulgarian owner guide (D4-24) says: **«едно или две кратки изречения, до 120 знака»**.
- **Verification is a measurement, not an opinion:** the executor runs
  `scripts/render-check.sh` at 360 × 640 with a 120-code-point message active and records the
  rendered banner height and the resulting card-1 bottom edge in the plan's summary. A banner
  taller than **180px** at 360px is a defect.

**Structured data (D4-27):** the same period emits Google's documented closed-for-a-period
shape into `jsonld.php` — `"opens":"00:00","closes":"00:00","validFrom":…,"validThrough":…`,
with no `dayOfWeek`, inside `openingHoursSpecification`. The banner and the JSON-LD read the
**same two settings keys**; they cannot disagree.

### C-3 — Contact form (`.form`) · CONTACT-03, CONTACT-05, D4-12…D4-15

**ONE partial, TWO callers.** `includes/contact-form.php` exposes
`torin_render_contact_form($values, $errors)`. It is included by `kontakti.html` (empty state)
and by `contact-send.php` (error re-render, repopulated). There is exactly one copy of this
markup. A second copy is how the two renderings start to disagree.

**Form element:**

```html
<form class="form" id="contact-form" action="contact-send.php" method="post"
      enctype="multipart/form-data" novalidate>
```

| Attribute | Value | Why |
|---|---|---|
| `enctype` | `multipart/form-data` | required for the file input; without it `$_FILES` is empty and the failure is silent |
| `novalidate` | **present** | Native constraint-validation bubbles are rendered in the **browser's** locale, not the page's. A Bulgarian visitor on an English-locale phone would get English error bubbles on a site whose hard constraint is "all content in Bulgarian", and they cannot be translated or styled. `novalidate` suppresses them; our own Bulgarian messages replace them |
| `required` / `type="email"` / `inputmode` / `autocomplete` | **kept anyway** | They still drive the mobile keyboard, autofill, and the accessible required state. Only the *bubbles* are suppressed |

**Single source for validation strings.** Each field carries `data-err="…"` holding the exact
Bulgarian message the **server** would produce. The client-side validator reads that attribute
and renders it. PHP is the one writer; JS cannot drift from it, and with JS off the same
string arrives server-rendered.

**Layout:** single column, `max-width: var(--form-measure)` (34rem). One column at every
width — no two-up rows. A two-up row on a repair form buys ~80px of vertical space and costs a
predictable tab order and a reliable error position.

**Field order — chosen to minimise drop-off (D4-21):**

| # | Field | `name` | Control | Required |
|---|---|---|---|---|
| 1 | Модел на устройството | `device` | `input type="text"`, `autocomplete="off"` | yes |
| 2 | Какво прави устройството | `fault` | `textarea`, min-height 8rem, `maxlength` clamped to the Telegram 1024-char caption budget | yes |
| 3 | Снимки на повредата (по избор) | `photos[]` | `input type="file" multiple accept="image/jpeg,image/png,image/webp"` | **no** (D4-12) |
| 4 | Вашето име | `name` | `input type="text"`, `autocomplete="name"` | yes |
| 5 | Телефон | `phone` | `input type="tel"`, `inputmode="tel"`, `autocomplete="tel"` | yes |
| 6 | Имейл | `email` | `input type="email"`, `inputmode="email"`, `autocomplete="email"` | yes |
| 7 | Съгласие | `consent` | `input type="checkbox"` — §C-5 | yes |
| — | honeypot + time-trap | §C-6 | hidden by contract | — |
| — | `Изпратете запитване` | — | `button type="submit" class="btn btn--primary"` | — |

**The order is the design decision, and it is deliberate.** The visitor arrived wanting to
describe a broken laptop. Asking for that first meets them where they are; asking for their
phone number first reads as a gate. By the time they reach the contact fields they have
already invested effort, which is the whole mechanism. Photos sit directly after the
description because that is the moment "show us" makes sense — and because a *clearly optional*
field placed mid-form is abandoned far less often than one placed at the end, where it reads
like a final obstacle. Consent is last, immediately above the submit button, where it reads as
part of submitting rather than as a checkpoint.

**Field anatomy — identical for every field, no exceptions:**

```html
<div class="field">                              <!-- .field--invalid when errored -->
  <label class="field__label" for="device">Модел на устройството <span class="field__req" aria-hidden="true">*</span></label>
```

| Rule | Value |
|---|---|
| Label | **always visible, always above the control.** Never a placeholder, never floating |
| Required marker | `*` in `--c-danger`, `aria-hidden="true"`. Requiredness reaches assistive tech through the `required` attribute, not through a red glyph. A legend under the submit reads «Полетата със * са задължителни.» |
| `aria-describedby` | names **both** the helper and the error node, unconditionally. Toggling the id list is a common source of stale references — toggle `hidden` on the node instead |
| Invalid state | `aria-invalid="true"` on the control, `hidden` removed from `.field__error`, `.field--invalid` on the wrapper |
| Vertical rhythm | `--sp-lg` (24px) between `.field`s; `--sp-xs` (4px) label→control and control→helper/error |

**Control styling (`.field__control`) — the exact declarations:**

| Property | Value |
|---|---|
| `min-height` | 48px (`textarea`: 8rem) — matches `.btn` exactly |
| `padding` | `0 var(--sp-md)` (`textarea`: `var(--sp-sm) var(--sp-md)`) |
| `background` | `var(--c-surface-3)` `#e7ecf4` — the Phase-2 declared "input fill" role, used for the first time |
| `border` | `1px solid var(--c-border-strong)` `#77869e` |
| `border-radius` | `var(--r-sm)` 6px — the Phase-2 declared "inputs" radius |

| `:focus-visible` | inherited `3px solid var(--c-focus)`, `outline-offset: 2px` — 7.16:1 on the fill. Text inputs match `:focus-visible` on pointer focus too, so no extra rule is needed |
| `[aria-invalid="true"]` | `border-width: 2px; border-color: var(--c-danger)` — 5.51:1 on the fill |
| `transition` | `background-color var(--dur-fast) var(--ease)` only. **`border-color` may not animate** — the inherited motion contract permits exactly `transform`, `opacity` and `background-color` |

**Submit button:** `.btn .btn--primary`, label «Изпратете запитване» — 181.5px of text at

a double-submit guard, not a spinner; there is no spinner anywhere in this design system and
Phase 4 does not introduce one. With JS off there is no submitting state and the server-side
rate limiter is the double-submit guard.

### C-4 — Photo upload control · D4-13, D4-14, P-6, P-7

**The native control stays native.** `<input type="file" multiple>` styled through
`::file-selector-button` — Baseline widely available, keyboard and screen-reader behaviour
untouched, zero JS required to look right. The
visually-hidden-input-plus-styled-`<label>` pattern is **forbidden here**: it routinely loses
the focus ring, which is the one thing `base.css` says is never suppressed.

| Part | Contract |
|---|---|
| `::file-selector-button` | styled as `.btn--secondary` — transparent fill, `2px solid var(--c-ink-deep)`, `--c-ink-deep` text, `min-height: 44px`, `border-radius: var(--r-md)`, `margin-inline-end: var(--sp-md)`, `cursor: pointer` |
| Wrapper | the control sits on the page background, **not** on the `--c-surface-3` input fill — it is a button, not a text field, and giving it a field fill would make it read as an empty input |
| Label | «Снимки на повредата (по избор)» |
| Helper | «Не е задължително. До 5 снимки, всяка до 10 MB. Смаляваме ги автоматично преди изпращане.» — 2 lines at 360px |
| Accept | `accept="image/jpeg,image/png,image/webp"` — a hint to the picker, **never** the enforcement point |

**Selected-file list (progressive enhancement, JS only) — `.filelist`:**

One row per file: a **48 × 48 px preview**, the file name (truncated with `text-overflow:
ellipsis`, `min-width: 0` on the flex child so it can actually shrink), the post-downscale
size, and a remove button.

- The preview is drawn from the **already-downscaled bitmap** that the resize step produced.
  No second decode, no second allocation. A preview that costs an extra full-resolution decode
  on a low-end Android is exactly the kind of thing DESIGN-02 exists to prevent.
- Preview: `object-fit: cover`, `border-radius: var(--r-sm)`, `--c-surface-3` fill behind it.
- Remove button: `.filelist__remove`, 44 × 44 hit area, `torin_icon('close')`, accessible name
  «Премахнете {име на файла}» — **never a bare «×»**, which announces as "times" or as nothing.
- With JS off, `.filelist` never renders. The native input's own "3 files selected" text is the
  entire feedback, and that is acceptable: the server tells the truth either way.

**Orientation (P-7):** the browser step uses
`createImageBitmap(file, { imageOrientation: 'from-image' })` — **not** `<img>` +
`drawImage()`, which discards EXIF orientation and delivers every portrait phone photo
sideways. This is a *visual* contract, not an implementation note: the owner receiving a
rotated cracked-screen photo is a user-visible defect, and **a test run only with a screenshot
or a desktop-exported JPEG passes a broken pipeline**, because neither carries an orientation
tag.

**The downscale is an optimisation, never a limit (P-6).** The server enforces count,
per-file size, total size, MIME, decodability and dimensions unconditionally and identically
whether or not JS ran. The no-JS path is the same path with one fewer optimisation, not a
lesser path.

**Interaction contract when the resize is still running at submit time:**
the button label becomes «Подготвяме снимките…» and the submit is deferred until the work
finishes, with a **10-second ceiling** after which the form submits the originals and lets the
server decide. The form must never appear to hang, and it must never silently drop a photo.

```html
<div class="field consent">
```

### C-6 — Honeypot and time-trap · CONTACT-03

These are the only two controls on the site that must be **invisible to humans, unreachable by
keyboard, and unannounced by assistive technology**. That is a visual/interaction contract, so
it belongs here rather than in the security plan.

```html
<div class="hp" aria-hidden="true">
  <label for="website">Уебсайт</label>
  <input id="website" name="website" type="text" tabindex="-1" autocomplete="off">
</div>
<input type="hidden" name="t" value="…HMAC-signed render timestamp…">
```

| Rule | Value | Why |
|---|---|---|
| Field name | a plausible one — `website`. **Never** `honeypot`, `hp`, `leaveblank` or anything naming the trap | the name is in the served HTML |
| Hiding | `.hp { position: absolute; left: -100vw; top: -100vh; }` **declared in `components.css`, never inline** | an inline `style="display:none"` on a form field is the single most recognisable honeypot signature in the served markup |
| `aria-hidden="true"` on the **wrapper** | removes label and input from the accessibility tree together | a screen-reader user must never be asked for a website |
| `tabindex="-1"` | keeps it out of the tab order | a keyboard user must not be able to land in it |
| **`autocomplete="off"`** | **load-bearing, not hygiene** | a password manager or browser autofill filling a hidden field is the number-one source of honeypot false positives — a real customer's enquiry silently discarded, which is the worst failure this form has |
| Time-trap window | reject **below ~3 seconds** and **above a couple of hours** | the lower bound catches bots; the upper bound only needs to stop replay. Coupled to the `no-store` header in §C-2 |

**No CAPTCHA. No visible challenge of any kind.** This is a design decision, taken under
CONTEXT's "Claude's Discretion" grant, and it is recorded so it is not revisited casually:

1. reCAPTCHA and its peers reintroduce exactly the third-party-cookie problem D4-18 was chosen
   to avoid, which would put a consent banner in front of a site whose entire premise is
   getting a worried customer to their problem fast;
2. it is a measurable conversion cost on the one form the business depends on;
3. it is a third-party JS payload against DESIGN-02;
4. honeypot + time-trap + rate limiting handle the actual threat here, which is commodity
   form-spam bots, not a targeted adversary.

**Reuse `.notice`, `.notice--error`, `.notice--success` verbatim.** Phase 2 built all three and
its own source comment says why: *"they are built now because the tokens and the Bulgarian copy
are specified now… their appearance is a carried-forward visual check."* Phase 4 is where that
check is discharged. **Do not author a second band component.**

| State | Where | Component | Behaviour |
|---|---|---|---|
| **Success** (any channel succeeded — D4-08) | `msg.html` | page copy, no band needed | `contact-send.php` replies **303 See Other → `msg.html`**. POST/Redirect/GET, so a refresh cannot resubmit and cannot re-notify the owner |

| **All channels failed** (D4-10) | re-rendered `kontakti.html` | `.notice--error` | the phone number is **composed from `$site['phones'][0]`**, never typed as a literal. The legacy `mailer.php` redirected to `msg.html` regardless of whether `mail()` returned false; this form does not |
| **Oversized POST** (`post_max_size` exceeded → `$_POST` and `$_FILES` both empty) | re-rendered `kontakti.html` | `.notice--error` | detected explicitly as `CONTENT_LENGTH > 0 && empty($_POST)`. Without this the visitor sees a blank form and no explanation, and the handler cannot tell "too big" from "no submission" |
| **Rate-limited** | re-rendered `kontakti.html` | `.notice--error` | names the wait and the phone number |

**Error-summary band anatomy:** the band carries an `h2` at `--fs-title`, a one-line body, and
— when there are field errors — a `<ul>` of in-page links to each failing control (`href="#device"`).
On a phone the first invalid field is often off-screen; a link list is what makes the band
actionable rather than decorative. The band is focused programmatically on render
(`tabindex="-1"` + `.focus()`) so screen-reader and keyboard users land on the explanation
rather than at the top of the document.

**One new icon — `alert`.** The icon set has `check` (success), `close` (a dismiss glyph) and
`clock`, but nothing that reads as a warning. Using `close` in an error band reads as "close
this". Add exactly one 16th glyph: a triangle with an exclamation mark, on the house
`viewBox="0 0 24 24"`, `fill="none"`, `stroke="currentColor"`, `stroke-width="1.75"`, round
caps and joins, `aria-hidden="true" focusable="false"`, ~200 B. The `star` exception stays the
only `fill` glyph in the file.

**`msg.html` changes (S9):** it already says the right thing about a missing reply within one
working day — keep that sentence. Add: the enquiry and any photographs have been sent, and a
confirmation email is on its way (D4-09). Set `$torin_robots = 'noindex, follow'`. **Do not
restate the hours or the phone numbers in the body** — `site-config.php` owns both and
`footer.php` renders them at the bottom of that very page; a second copy is the copy that gets
forgotten when the hours change.

### C-9 — Analytics instrumentation · ANALYTICS-01, D4-18…D4-21, P-2

This is an **interaction** contract because getting it wrong breaks the site's primary
conversion action.

> **`data-umami-event` is FORBIDDEN on any `tel:` or `mailto:` anchor.** The shipped tracker,
> for any `<a>` carrying the attribute, runs `e.preventDefault()`, fires its beacon, and
> re-navigates inside `.finally()` via `location.href`. On a `tel:` link that puts the dialer
> behind a third-party network round trip, in a task that no longer carries the user gesture —
> delayed on a flaky mobile connection, and never at all where the browser enforces
> gesture-bound custom-scheme navigation. **A manual test done on a desktop passes this
> defect**, because `tel:` does nothing there either way.

**The one permitted mechanism** is a passive, delegated, capturing listener in
`js/analytics.js` that calls `umami.track()` and returns — no `preventDefault`, no `await`,
nothing in the activation path. Umami's own transport is `fetch(…, { keepalive: true })`, so
nothing is lost to navigation. One mechanism for every event on the site, including the ones
where the declarative attribute would have been safe.

**`data-slot` on all 7 rendered `tel:` anchors:**

| Slot value | Source |
|---|---|
| `hero` | `src/index.html:57` |
| `cta` | `src/index.html:296` |
| `callbar` | `src/index.html:342` |
| `category` | `src/includes/category-page.php:553` |
| `footer-list` | `src/includes/footer.php:50` — a loop over `$site['phones']`, so **3 rendered anchors from 1 source line** |
| `footer-cta` | `src/includes/footer.php:73` |

The same `data-slot` attribute goes on the 5 new «Пишете ни» anchors (§C-7), so call and write
are comparable slot-for-slot.

**Event contract — D4-21's four questions, and what each costs.**
Umami's pricing FAQ: *"Each website pageview counts as one event. If you save event properties,
each data property stored counts as one event."* So an event with one property costs **2**.

| Event | Fires on | Properties | Cost | Answers |
|---|---|---|---|---|
| *(pageview)* | automatic | — | 1 | **service-page visits — costs nothing extra** |
| `call-click` | click on any `a[href^="tel:"]` | `slot` | 2 | which call surface works |
| `write-click` | click on any `a[href="kontakti.html"]` carrying `data-slot` | `slot` | 2 | call-vs-write split |
| `form-start` | first `focus` on any form control, once per page | — | 1 | how many people begin |
| `form-photos` | first time ≥1 file is chosen | — | 1 | **drop-off point 1** |
| `form-consent` | first time the consent box is checked | — | 1 | **drop-off point 2** |
| `form-submit` | on submit (client) | — | 1 | how many attempt |
| `form-error` | server-rendered on the error page | `field` | 2 per field | which field rejects people |
| `form-sent` | server-rendered on `msg.html` | — | 1 | how many complete |

The funnel `form-start → form-photos → form-consent → form-submit → form-sent` **is** the
drop-off measurement: the step where the count falls is the step that loses people. A completed
enquiry costs ≤ 6 events against a 100,000/month allowance.

**Loading contract:**

| Rule | Value |
|---|---|
| Tracker | `<script defer src="https://cloud.umami.is/script.js" data-website-id="…">` in `header.php`, **once** |
| `data-performance` | **omitted.** Web-Vitals collection is opt-in and would add payload and events for a question nobody asked |
| `preconnect` / `dns-prefetch` to `cloud.umami.is` | **forbidden.** It would open a third-party connection in competition with the Sofia Sans Cyrillic preload, which is the LCP-critical resource. Analytics never races the font |
| `js/analytics.js` | first-party, `defer`, site-wide (the `tel:` listener is needed on every page). Form handlers inside it are guarded by `if (document.getElementById('contact-form'))` |
| `js/photo-resize.js` | **contact page only.** Never in the shared head |
| No-JS | zero analytics. Accepted and stated: the counts under-report by the no-JS share, which is small and which is the price of not shipping a tracking pixel |
| `uslovia.html` | **must disclose Umami by name, its purpose, and that data leaves the EU/EEA** (§S11). "No consent banner needed" is not "no disclosure owed" — GDPR Art. 13 transparency is a separate obligation from the ePrivacy Art. 5(3) consent trigger |

## Performance Budget · DESIGN-02

**Measured live baseline** (`https://torin.bg/new/`, 2026-09-17, homepage, wire bytes):

| Asset | Wire | Encoding |
|---|---:|---|
| `index.html` | 5,284 B | gzip |
| `css/base.css` | 1,684 B | gzip |
| `css/layout.css` | 546 B | gzip |
| `css/components.css` | 2,808 B | gzip |
| `js/site.js` | 1,175 B | gzip |
| `fonts/sofia-sans-cyrillic.woff2` | 25,568 B | none (already compressed) |
| `img/torin-logo.png` | 19,147 B | none |
| `favicon.ico` | **31,662 B** | none |
| **Critical path (HTML + CSS + JS + font)** | **≈37.1 KB** | — |

> **Phase 2's "the host serves no compression — every byte is wire cost" is FALSE as of
> 2026-09-17.** The origin returns `content-encoding: gzip` with `vary: Accept-Encoding` on
> `text/html`, `text/css` and JS. `components.css` is 36,519 B on disk and **2,808 B on the
> wire** — the ~40 KB of design-reasoning comments across the CSS cost **≈0** to visitors.
> See **§Conflicts C-3**. The CSS budget is therefore restated in **wire bytes**, and the
> comments are not to be stripped.

**Phase-4 budget:**

| Item | Budget | Note |
|---|---:|---|
| CSS delta, site-wide (banner + form + filelist), **gzipped** | **≤ 1.5 KB** | the form is the largest new component in the system; most of its declarations reuse existing tokens |
| CSS total, all files, gzipped | **≤ 7 KB** | 5,038 B today |
| First-party JS delta, site-wide (`js/analytics.js`), gzipped | **≤ 1.0 KB** | a delegated listener and an event map |
| First-party JS, contact page only (`js/photo-resize.js`), gzipped | **≤ 2.0 KB** | this is the phase's main new JS, and it is on one page of twenty |
| Third-party JS | **exactly 1 origin, ≤ 2.5 KB gzipped, `defer`** | `cloud.umami.is/script.js` measures 4,757 B raw / 2,333 B gzipped |
| New icons | **exactly 1** (`alert`, ~200 B raw) | the icon set stays inside its ≤5 KB budget |
| New fonts, new families, new weights | **zero** | |
| Blocking resources added | **zero** | no new stylesheet in the critical path; every script `defer` |
| `preconnect` / `dns-prefetch` added | **zero** | analytics must never compete with the Cyrillic font preload |

**Forbidden outright, restated because this is the phase where they get proposed:** jQuery,
jQuery UI, ScrollMagic, pagePiling, Alpine.js, any CSS framework, any icon webfont, an embedded
Google Maps iframe, a CAPTCHA widget, a spinner library, a date picker, and an image-cropping
library.

**Caching (D4-34) — the UI-visible constraint:** CSS and JS may go to a one-year lifetime
**because every asset URL already carries `?v=<filemtime>`**. Two exclusions that are not
optional:

1. **`fonts/sofia-sans-cyrillic.woff2` stays unstamped.** Stamping it would break the
   byte-match with `base.css`'s `@font-face src` (downloading the subset twice on every cold
   visit) **and** would blind `scripts/probes/font-swap.js`, whose fallback pass blocks
   `['*.woff2','*.woff','*.ttf']` — a glob that stops matching the moment a query string is
   appended. A stamped woff2 does not fail that gate, it makes it report a flawless
   `maxAbsDeltaPx: 0` while measuring nothing.
2. **`kontakti.html` sends `Cache-Control: no-store`** (§C-2), and the `ExpiresByType
   text/html` rule must carry that exception explicitly rather than by accident.

## Conflicts & Corrections

Three measured departures. Each names what it departs from, the number that forced it, and
what it would cost to go the other way.

### C-1 — ⚠ **D4-17's CTA label does not fit, and D4-17's own stated rationale is what fails**

CONTEXT D4-17: *"«Изпратете запитване», linking to the contact page, replaces the Viber button
in all four CTA slots… This preserves the call-first / write-second pairing the design is built
around **and needs no layout change**."*

The label is 19 code points against the Viber label's 16, and **182.8px of Sofia Sans at
`--fs-body`/700 against 141.2px** — a 42px increase on a component that `components.css:386`
already documents as width-critical. Full button width including the inherited 48px of inline
padding, the 1.25em icon and the 8px gap:

| Slot | Constraint | «Пишете във Viber» | «Изпратете запитване» | «Пишете ни» |
|---|---|---|---|---|
| `.callbar` @360px | 180px (half the bar) | 186.7 — **already overflows today** | **228.3 — overflows by 48px** | **134.4 — fits, 46px slack** |
| `.callbar` @320px | 160px | 186.5 — overflows | 228.1 — overflows | 134.3 — fits |
| footer column @560px | 233.6px (2-up grid) | 221.5 — fits | **263.9 — overflows → 2-line button** | 168.3 — fits |
| footer column @900px | 246.7px (3-up grid) | 226.4 — fits | **270.0 — overflows → 2-line button** | 171.6 — fits |
| footer column @1152px | 330.7px | 228.0 — fits | 272.1 — fits | 172.7 — fits |
| hero pair @560px | 515.2px content box | 455.7 — one row | 498.1 — one row, **17px slack** | 402.5 — one row |
| category CTA, all widths | full container | fits | fits | fits |

So «Изпратете запитване» would render as a **two-line button** in the footer between ~560px and
~1100px — sitting beside a 48px «Обадете се» button, which destroys exactly the equal-weight
pairing D4-17 says it preserves — and would overflow the sticky call bar on every common phone
width.

Research P-12 caught the callbar and proposed a per-slot short label, but concluded *"the full
label is fine in the hero, footer and category-page slots, which are not width-constrained."*
**The footer column is width-constrained**, at 233.6px / 246.7px, and the measurements above
show it.

**Resolution — one label for all five slots: «Пишете ни» (9 cp, 88.7px).**

- It fits every slot at every width from 320px up, with ≥45px of slack in the tightest one.
- It is a **verb + pronoun in the formal plural**, exactly parallel to «Обадете се» — so the
  call-first / write-second pairing is preserved *better* than by the locked string, which is a
  verb + abstract noun and breaks the parallel.
- Per-slot label variants were rejected: the same destination reached by two different names on
  the same page is a navigation defect, and it doubles the copy surface for every future edit.
- **«Изпратете запитване» is not lost.** It becomes the contact page's `h2` and its submit
  button label — where the column is 34rem wide and the phrase fits comfortably. It is also
  where Phase 2's own copywriting contract already assigned it: *"Secondary CTA (form submit) —
  `Изпратете запитване`"*. This resolution is more faithful to the inherited contract than
  D4-17 is.

> **⚠ Requires owner/user sign-off.** D4-17 is a LOCKED decision and this changes the visible
> string on five surfaces. The decision it rests on is preserved in full — the Viber button goes,
> the CTA leads to the contact page, the pairing survives — but the label differs. **Confirm
> before planning.** If the full label is insisted upon, the fallback is: «Изпратете запитване»
> in the hero and category slots, «Пишете ни» in the callbar and footer, and the two-name
> inconsistency accepted and recorded.

### C-2 — Correction to `components.css:386` — the callbar sizing comment omits the icon

The shipped comment reads: *"The label «Пишете във Viber» measures ~141px… at 360px each half is
180px, so the button's normal `--sp-lg` side padding (48px total) would overflow it."* The
padding was duly reduced to `--sp-sm`.

The arithmetic left out `.btn svg { width: 1.25em }` **and** `.btn { gap: var(--sp-sm) }` —
21.3px + 8px = **29.3px**. The true width is 141.4 + 16 + 29.3 = **186.7px against 180px**, so
the shipping callbar button **already overflows at 360px and below**, and is saved from visible
breakage only by `.callbar .btn { min-width: 0 }` letting the flex item shrink and the label
wrap to two lines inside a 56px bar. It fits from ~390px upward.

This is a live, currently-shipping defect and **the CTA swap is the opportunity to fix it, not
to inherit it.** «Пишете ни» clears it at 320px with 26px to spare.

*Method note:* the arithmetic above reproduces the comment's own 141px figure to within 0.2px
from the shipped woff2, which is why the additional 29.3px is a correction and not a competing
estimate.

### C-3 — ⚠ Correction to `02-UI-SPEC.md` — the host **does** serve compression

Phase 2's CSS budget table is headed *"CSS budget: **≤ 20 KB raw total.** Host serves **no
compression** — every byte is wire cost."*

Measured 2026-09-17 against `https://torin.bg/new/`: the origin returns
`content-encoding: gzip` with `vary: Accept-Encoding` on HTML, CSS and JS.
`components.css` is 36,519 B on disk and **2,808 B on the wire**. Total CSS: 60,671 B on disk,
**5,038 B on the wire**. Roughly 40 KB of the 60 KB on disk is design-reasoning comments, and
they cost visitors approximately nothing.

Consequences, all of which matter to this phase:

1. The "≤20 KB raw" budget is **already exceeded threefold** and has been since Phase 2
   shipped — it was measuring the wrong thing, not being violated.
2. **The comments must not be stripped.** They are this project's most valuable asset and they
   are free. Any Phase-4 proposal to minify CSS "for DESIGN-02" is optimising a 0-byte problem
   while destroying the record.
3. The Phase-4 budget in §Performance Budget is stated in **gzipped wire bytes**, which is the
   only figure a visitor experiences.
4. The `.htaccess` work (D4-34, Pattern A-5) must confirm the compression configuration
   **survives promotion to root** — the sweep should assert `content-encoding: gzip` on
   `css/components.css` at the real domain, not merely a 200.

### C-4 — D4-26 undercounts the duplicated hours: there are **three** copies, not two

D4-26 says the hours are written twice — `site-config.php:62` and `jsonld.php:64-71`. There is a
third: `site-config.php:291`, `'notice' => 'Работно време: понеделник – петък, 8:00 – 16:00 ч.'`,
rendered by `footer.php:27` as the `.notice--info` band on all 19 pages.

Editing `settings.txt` must change **all three**, or the owner will silently tell Google one
thing, the footer band another, and the footer hours line a third. The `notice` string is
composed from the settings values, never typed.

### C-5 — Research P-13 stands: "unlisted means closed" is not what Google documents

Recorded here because it has a **user-visible** consequence rather than only a JSON one: a
weekend that Google reads as open sends a customer to a locked door. Emit **three**
`OpeningHoursSpecification` entries — `Mo–Fr 08:00–16:00`, `Saturday 00:00/00:00`,
`Sunday 00:00/00:00` — matching Google's own documented shape. D4-25's *decision* (closed
weekends, unstated on the page) is unaffected; this is only about the JSON.
