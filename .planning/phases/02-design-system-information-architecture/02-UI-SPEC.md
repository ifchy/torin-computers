## Spacing Scale

Declared values (all multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| `--sp-xs` | 4px | Icon-to-label gap, chevron offset |
| `--sp-sm` | 8px | Symptom-line gap under a card title, badge padding |
| `--sp-md` | 16px | Default element spacing, card inner padding (mobile), grid gutter floor |
| `--sp-lg` | 24px | Card inner padding (≥35rem), CTA button gap, `<details>` body padding |
| `--sp-xl` | 32px | Layout gaps, category grid gap, nav dropdown padding |
| `--sp-2xl` | 48px | Major section breaks, footer column gaps |
| `--sp-3xl` | 64px | Page-level section rhythm ceiling |

**Exceptions (2, both justified):**

1. **44px minimum touch target.** Every interactive control — nav toggle, disclosure button, `<summary>`, buttons, footer phone links — has a hit area of **≥ 44 × 44 px**. Not a spacing token; a floor asserted on control sizing. Buttons ship at **48px** tall.
2. **Non-token fluid values for container and rhythm** (these are formulas, not scale steps, and must not be hand-substituted with arbitrary px):
   - `--container: 72rem` (1152px max content width)
   - `--gutter: clamp(1rem, 4vw, 2rem)`
   - `--section-y: clamp(2.5rem, 6vw, 4.5rem)` — vertical section rhythm

No other value may appear in a margin/padding/gap declaration.

## Typography

**Family:** `--font-sans: 'Sofia Sans', 'Segoe UI', Roboto, 'Helvetica Neue', Arial, sans-serif`
Single family for headings and body (D-06a). Fallbacks chosen for Cyrillic capability on every platform.

**Loading contract:**
- `font-display: swap` — text visible immediately; invisible text works against the core value.
- Preload **the Cyrillic subset only** (`crossorigin` required even same-origin, or the file downloads twice).
- Latin subset loads on demand via `unicode-range` — but Latin **will** appear (phone numbers, `USB`, `HDMI`, `BGA`, `Viber`), so budget both: **66 KB**.
- `@font-face` declares `font-weight: 400 700` so a stray `font-weight: 800` clamps to 700 instead of introducing a third weight.

### Sizes — exactly 4. No fifth size exists.

| Role | Token | Size | Weight | Line Height | Applied to |
|------|-------|------|--------|-------------|------------|
| Display | `--fs-display` | `clamp(2.00rem, 1.55rem + 2.00vw, 3.00rem)` → 32→48px | 700 | 1.15 | Hero `h1` only |
| Heading | `--fs-heading` | `clamp(1.55rem, 1.30rem + 1.11vw, 2.05rem)` → 24.8→32.8px | 700 | 1.20 | Section `h2` |
| Title | `--fs-title` | `clamp(1.20rem, 1.11rem + 0.42vw, 1.40rem)` → 19.2→22.4px | 700 | 1.25 | Card `h3`, `<summary>`, category-page `h3`, footer column heads |
| Body | `--fs-body` | `clamp(1.0625rem, 1.03rem + 0.15vw, 1.125rem)` → 17→18px | 400 | 1.65 | Everything else — paragraphs, symptom lines, nav links, button labels, footer contact lines, legal line |

**There is deliberately no `--fs-small`.** Small print (footer copyright, form helper text) uses `--fs-body` differentiated by `--c-ink-muted`, not by size. Rationale: Sofia Sans's x-height is **488/1000** vs Inter's 546 — a 15px Sofia Sans line reads like ~13.4px of Inter, which is below a comfortable floor for a mobile-heavy, non-young audience reading Cyrillic. See §Conflicts C-2.

### Weights — exactly 2.

| Token | Value | Use |
|---|---|---|
| `--fw-regular` | 400 | All body copy, nav links, symptom lines, button labels |
| `--fw-bold` | 700 | All headings (`h1`–`h3`), `<summary>`, active nav item, phone numbers in the footer |

No 500, no 600, no 800. Emphasis inside body copy uses `--fw-bold`; there is no medium weight to reach for.

### Cyrillic-specific rules (derived from measured Sofia Sans metrics)

| Rule | Value | Why |
|---|---|---|
| Body base | **17px**, not 16px | x-height 488 vs Inter 546 (−11%); Sofia Sans is also ~8% narrower |
| Body line-height | **1.65** | Bulgarian Cyrillic lowercase has markedly fewer ascenders/descenders → flatter word shapes → tight leading destroys scanability. The current site's `business.css` independently landed on `1.7em` |
| Measure | `--measure: 66ch` on `p`, `li` | Cap at 60–70 chars |
| Heading wrap | `text-wrap: balance` on `h1`–`h3` | Category names run to 33 chars and produce ugly one-word last lines. Degrades to nothing where unsupported |
| Letter-spacing | **`normal` everywhere.** No tracking adjustments | Cyrillic is not Latin; tracking tuned by eye on Latin damages Cyrillic rhythm |
| Uppercase | **Forbidden** as a styling device (`text-transform: uppercase`) | Bulgarian uppercase Cyrillic loses the distinctive lowercase letterforms that are the entire point of D-06a, and lengthens already-long strings |

### Focus visibility

Single rule, applied to every focusable element. Never `outline: none` without a replacement.

```css
:focus-visible { outline: 3px solid var(--c-focus); outline-offset: 2px; border-radius: var(--r-sm); }
.hero :focus-visible, .site-footer :focus-visible, .btn--primary:focus-visible {
  outline-color: var(--c-focus-on-dark);
}
```

`--c-focus` = `--c-link`. On the amber primary button the ring uses `--c-focus-on-dark`? No — on amber the ring uses `--c-on-brand` `#16223a` (**10.14:1**), because `#ffd84d` on amber is invisible. Stated explicitly so it is not "simplified" into one rule.

### Motion

`--dur-fast: 140ms`, `--dur-base: 200ms`, `--ease: cubic-bezier(.2,.7,.3,1)`.
Only three properties may animate: `transform`, `opacity`, `background-color`. No height/width/top/left animation.

## Layout & Breakpoints

**Two breakpoints only.** Both derived from RESEARCH §5a's Bulgarian browser baseline (100% evergreen engines; Baseline "Widely available" is the target).

| Name | Value | What changes |
|---|---|---|
| `sm` | `35rem` (560px) | Category card flips horizontal → vertical; grid 1 → 2 columns; CTA buttons gain breathing room |
| `md` | `56.25rem` (900px) | Hamburger → inline nav; dropdown becomes absolutely positioned; grid 2 → 3 columns; sticky mobile CTA bar hidden |

Media queries. **Not** container queries (one card, one container context — no benefit, extra concept).
**No `repeat(auto-fit, minmax())` on the category grid** — with a fixed six, auto-fit produces 4+2 and 5+1 orphan rows at intermediate widths. Explicit columns: **1 → 2 → 3**, giving 6 → 3+3 → 2+2+2.

### Above-the-fold arithmetic (D-30's actual purpose, computed at 360 × 640)

| Element | Height |
|---|---|
| Header bar (mobile) | 56px |
| Hero `min-height: clamp(16rem, 42svh, 22rem)` → 42% of 640 | 269px |
| Section padding-top (`--section-y` floor) | 40px |
| `h2` «Какво ремонтираме» + eyebrow + margin | 50px |
| **Category card 1** (horizontal, 80px media, 2-line title + 2-line symptom) | 142px |
| **Card 1 bottom edge** | **557px** |
| Sticky mobile CTA bar occlusion | 56px → visible viewport 584px |
| **Verdict** | ✅ Card 1 fully visible, card 2's title begins at ~590px |

`svh` **not** `vh` — `100vh` on mobile is the *large* viewport (URL bar retracted), so a `vh`-sized hero is taller than what is actually visible on first paint. That is precisely the failure D-30 exists to correct.
`min-height`, **not** `height` — if the Bulgarian headline wraps to three lines the hero grows rather than clipping.

### 2. Услуги disclosure (`.nav`) — IA-02, D-18, D-19

**Pattern: W3C APG Disclosure Navigation. NOT `role="menu"`.** `role="menu"` makes screen readers announce a desktop-application menu and hands navigation to arrow keys — wrong for six links, and a common damaging mistake.

Nav items (D-18), **5 total, 46 characters**: `Начало` (6) · `Услуги ▾` (6) · `Лаптопи и части` (15) · `Тествай сам` (11) · `Контакти` (8).

| Contract point | Requirement |
|---|---|
| Toggle element | `<button>`, never `<a href="#">` |
| ARIA | `aria-expanded` + `aria-controls` on the button; `aria-label="Основна навигация"` on `<nav>` |
| **Visual state source** | CSS drives **all** visual state off `[aria-expanded="true"]`. **Never** an `.is-open` class. This makes ARIA state and visual state structurally impossible to desynchronise — the single most common bug in hand-rolled dropdowns |
| Open trigger | **Click/tap only. No hover-open at any breakpoint.** Hover menus are unusable on touch and produce the "it opened when I moved past it" complaint |
| `Enter` / `Space` | Toggle |
| `Escape` | Close **and return focus to the controlling button**. Required by WCAG 2.1 SC 1.4.13 — not polish |
| `Tab` / `Shift+Tab` | Normal order. Focus leaving the nav region closes any open dropdown |
| Arrow keys | **Do not implement** — invites menu-role expectations |
| Click outside | Closes |
| Chevron | `[aria-expanded="true"] .nav__chevron { transform: rotate(180deg) }`, `--dur-fast` |
| Dropdown width | **`min-width: 22rem; max-width: 26rem`** — see C-3. One name per line, no wrapping, at full readable length (D-19) |
| Dropdown surface | `--c-surface-2`, `--r-lg`, `--sh-2`, `z-index: 20`, `padding: var(--sp-md)` |
| Dropdown item | `--fs-body`, `min-height: 44px`, `padding-inline: var(--sp-md)`, hover/focus fill `--c-surface-3` |
| Active page | 3px `--c-brand` keyline under the top-level item + `--fw-bold` + `aria-current="page"` |

**Mobile form (`< 56.25rem`) — one implementation, CSS-only difference:**

Hamburger `<button class="nav__toggle">` toggles a **full-width in-flow panel**, and Услуги becomes an **inline accordion using the same disclosure button and the same JS**.

Rejected: a true overlay/drawer. It would require focus trapping, `inert`/`aria-hidden` on the background, and scroll locking — three more things to get right, for a five-item nav — and it would fork the ARIA contract into a second implementation that always rots first. An in-flow panel needs none of them.

```css
.nav__list { display: none; }
[aria-expanded="true"] + .nav__list { display: block; }
.nav__sub  { display: none; }
[aria-expanded="true"] + .nav__sub { display: block; }

@media (min-width: 56.25rem) {
  .nav__toggle { display: none; }
  .nav__list   { display: flex; gap: var(--sp-xl); align-items: center; }
  .nav__sub    { position: absolute; min-width: 22rem; max-width: 26rem; z-index: 20; }
}
```

**No-JS behaviour (accepted, documented):** with JS off, `aria-expanded` stays `false` and the six category links are unreachable *from the nav*. Mitigation is structural — **every category is reachable from the homepage card grid** by construction (IA-01), and the homepage is linked from `Начало`. Do **not** build a CSS-checkbox fallback; it would fork the ARIA contract for a case the card grid already covers.

**Header is NOT sticky.** A sticky header would eat 56px of mobile viewport, fighting D-30's above-the-fold arithmetic directly. Persistent reachability is provided instead by the sticky mobile CTA bar (component 5), which carries the actual conversion actions rather than the nav.

| Contract point | Requirement |
|---|---|
| **Indexability (D-11)** | Content is **real HTML in the served response**, unconditionally. Never JS-injected, never fetched on click, never `display:none`-ed by our own CSS (the element handles its own state) |
| Stable `id` on every `<details>` | Enables deep links from cards, nav and future internal links; the browser auto-opens `<details>` on fragment navigation |

| Chevron | `details[open] > summary .icon { transform: rotate(180deg) }` |
| Summary typography | `--fs-title`, `--fw-bold`, `--c-ink-deep`, `min-height: 44px`, `padding: var(--sp-md)`, `cursor: pointer` |
| Focus | `summary:focus-visible` gets the standard ring. Never suppressed |
| Panel | `--c-surface-2` fill, `--r-lg`, `--c-border` hairline, `--sp-lg` body padding, stacked with `--sp-sm` gaps |
| **Animation** | **Do not animate open/close.** Height animation requires `::details-content` (Baseline Newly available, Sept 2025) — enhancement only, and only inside `@supports selector(::details-content)`. The default instant toggle is the contract |
| `hidden="until-found"` | **Forbidden.** Baseline only Dec 2025 — too new to be load-bearing, and `<details>` already provides find-in-page auto-expand natively everywhere |

**⚠ Carry-forward, not silently resolved (RESEARCH Pitfall 8 / D-13 / OWNER-QUESTIONS #9):** collapsed content is reliably *indexed* but practitioner evidence suggests it is *weighted lower for ranking*. D-13 places the battery-regeneration differentiator (DIFF-02) here. That trade-off now has a second cost beyond reduced visibility. Do not treat D-13 as fully priced.

### C-1 — ⚠ CONFLICT with RESEARCH §5c: the proposed hero gradient fails WCAG AA

RESEARCH §5c specifies `linear-gradient(135deg, var(--c-ink-deep) 0%, #14488a 55%, var(--c-brand) 165%)`.
**Computed:** interpolating navy → amber passes through olive. At the 100% stop the background is `#747c56`, where white text is **4.41:1 — below AA's 4.5:1**. Theme A is worse at **4.13:1**. RESEARCH itself flagged its contrast figures as estimated (Assumption A6); this is the failure that assumption was hiding.

**Resolution:** the gradient stays inside the dark brand family (`--c-ink-deep` → `--c-ink-deep-2`), with amber demoted to a ≤16%-alpha corner radial kept away from text by `.hero__inner { max-width: 34rem }`. Worst-case white contrast rises to **6.48** (B) / **5.65** (A). D-31's requirement — brand gradient, no photography, genuinely different feel per theme — is fully preserved: navy `#0e305d → #1a4f8f` and electric `#0547dc → #1c56d8` are strongly distinct.

### C-2 — Deviation from RESEARCH §5d: no 15px small size

RESEARCH's scale includes `--fs-400: 0.9375rem` (15px). **Rejected.** With Sofia Sans's 488 x-height, 15px renders at the apparent size of ~13.4px of Inter — below a comfortable floor for a mobile-heavy audience reading Cyrillic, and inconsistent with RESEARCH's own §1e instruction to size *up* one step. The contract declares **4 sizes**; small print uses `--fs-body` differentiated by `--c-ink-muted`.

### C-3 — Correction to RESEARCH §3b: dropdown `min-width: 20rem` is ~1px short

The longest category name (33 chars) measures ≈ **17.0em** using RESEARCH §1e's own Sofia Sans advance widths (`н` 544, `о` 536, `м` 626 per 1000 em; ~0.56em/letter, ~0.26em/space) → **≈ 289px** at 17px body. RESEARCH's `min-width: 20rem` (320px) minus `2 × 1rem` padding leaves **288px** of content box. It wraps by a hair. **Bumped to `min-width: 22rem; max-width: 26rem`.** V6's 900px assertion ("all six names at full length on one line each") is what catches this if the estimate is off.

### C-4 — Factual correction to D-19 / CONTEXT.md: the "~184 characters" figure is stale

D-19 justifies the dropdown with "the six Bulgarian category names total ~184 characters". **Post-D-40 the six names total 142 characters** (measured). The 184 figure describes the *owner's original* names, before D-40's renaming.
**D-19's conclusion is unchanged and still correct** — 142 chars plus a logo still cannot sit inline in a desktop nav bar. Only the number is stale. Recorded so a later reader does not chase the discrepancy.

### C-5 — Deviation from RESEARCH §5b: the mobile card is horizontal, not vertical

RESEARCH §5b specifies a single vertical card with a `16/10` media box at all widths. **Computed at 360 × 640** that stacks to: header 56 + hero 269 + section padding 40 + `h2` 50 + media 205 = **620px before the first card title**, pushing it below the fold and **breaking D-30's own stated purpose** and RESEARCH V6 assertion ④ ("at least the first category card's media box and title visible without scrolling").

**Resolution:** below `35rem` the card is horizontal (80 × 60px media left, text right), giving a card-1 bottom edge of **557px** with two cards' titles above the fold. Same DOM, same classes, same `aspect-ratio` mechanism — **D-38's photo-swap guarantee is untouched.** Secondary benefit: six compact rows are far more scannable for a visitor with a specific symptom than six tall image cards.

### C-6 — Accepted exception to the 10% accent rule (D-16)

D-16 mandates two equal-weight amber primary CTAs, repeated in the hero, in each CTA block, and in the sticky mobile bar. Strictly, that exceeds a literal 10% accent budget. **Accepted deliberately:** the budget is asserted **per viewport**, and no viewport carries more than two amber fills plus one keyline. Recorded rather than silently exceeded, because a checker measuring per-page will flag it.

### C-7 — The two themes are not contrast-equivalent

Amber on the deep brand surface is **8.39:1** in Theme B but **3.77:1** in Theme A. In Theme A that pair is restricted to ≥24px bold text or non-text UI. This was not previously recorded anywhere and is an independent argument for D-02a's choice of Theme B.

### C-8 — Overrides `.claude/CLAUDE.md`

The repo's `CLAUDE.md` describes an Astro 7 + Tailwind 4 + Alpine.js stack. **That recommendation was not taken** (REQUIREMENTS.md "Out of Scope": *"CMS/WordPress or Node/Astro build pipeline"*). This contract is hand-authored CSS + PHP 5.2 includes, zero build tooling, and explicitly rejects Alpine.js (RESEARCH N-7: ~44 KB raw on a no-gzip host to replace ~50 lines). Deliberate rejection, not an oversight.
