<objective>
Turn the homepage from a hero into the six-category information architecture the phase exists
to deliver: six distinct cards driven by one data file, a symptom-organised catch-all for
everything else, the self-diagnostic feature block, and the repeated call-and-chat CTA.

Purpose: IA-01 is the requirement a visitor actually feels. The legacy homepage scrolls
fifteen undifferentiated icon boxes; a visitor with a cracked screen has to read all fifteen
to find out whether Torin fixes it. Six named categories with symptom lines beneath them is
the whole difference between "this shop might do it" and "this shop does exactly this".

The data file is the load-bearing part. Six names, six symptom lines, six slugs and six
publish flags are consumed by the card grid now, the Услуги dropdown in plan 02-03, and
`sitemap.xml` in Phase 4. Hand-typed hrefs would drift the first time a page publishes.

**Carried forward, not resolved here (D-13 / OWNER-QUESTIONS #9):** placing battery
regeneration in the folded section is a knowing downgrade of DIFF-02, and 02-RESEARCH §3c adds
a second cost the original trade-off did not price — collapsed content is reliably indexed but
practitioner evidence suggests it is weighted lower for ranking. Battery regeneration is a
genuine differentiator no competitor offers, i.e. exactly the content that could rank on its
own. Do not treat D-13 as fully priced; Phase 3 verification must treat DIFF-02 as knowingly
unmet rather than silently passing.

Output: a homepage a real visitor can use to find their problem and act on it.
</objective>

**`src/css/layout.css` — the grid.** `.cat-grid` as a CSS grid with `gap: var(--sp-xl)` and
**explicit** column counts: one column below `35rem`, two at `35rem` and above, three at
`56.25rem` and above. Do not use `repeat(auto-fit, minmax(...))` — with a fixed six it
produces 4+2 and 5+1 orphan rows at intermediate widths, which is exactly the undifferentiated
look IA-01 exists to remove.

**`src/css/components.css` — the card.** Build `.cat-card` to the UI-SPEC contract:
`--c-surface` white fill on a `--c-surface-2` section band so the cards read as raised,
`--r-lg` radius, `--sh-1` resting shadow, `position: relative`. On hover and `focus-within`,
`--sh-2` plus a 2px upward translate — transform and box-shadow only, no geometry animation.
`.cat-card__title` at `--fs-title`, `--fw-bold`, `--c-ink-deep`, with the `<a>` **inside** the
`h3` rather than wrapping the whole card, so the accessible name stays short and specific;
make the whole card clickable with a stretched-link pseudo-element on that anchor
(`content: ""`, `position: absolute`, `inset: 0`) so the anchor remains the only tab stop.
`.cat-card__symptoms` at `--fs-body`, `--fw-regular`, `--c-ink-muted`, capped at two lines at
360px.

`.cat-card__media` is the D-38 mechanism and must be built exactly as UI-SPEC specifies:
`display: grid` with `place-items: center`, `background: var(--c-surface-3)`,
`overflow: hidden`, and an `aspect-ratio` that sizes the box **independently of its contents**.
Two mutually exclusive child rules: a direct `svg` child at 42% width with
`color: var(--c-ink-deep)`, and a direct `img` child at 100% width and height with
`object-fit: cover`. This is what makes swapping an icon for an owner-supplied photo a
zero-layout-change edit.

Responsive card shape, which departs deliberately from 02-RESEARCH §5b for the reason UI-SPEC
C-5 computes: **below `35rem` the card is horizontal** — media on the left at `width: 5rem`
with `aspect-ratio: 4/3` (80 by 60 px), body on the right. At `35rem` and above it flips
vertical with the media on top at `width: 100%` and `aspect-ratio: 16/10`. Same DOM, same
classes, same aspect-ratio mechanism. A vertical card at 360px pushes the first card's title
to roughly 620px, below the fold, defeating D-30's entire purpose; the horizontal form puts
card 1's bottom edge at 557px.

**`src/index.html` — the grid section.** Below the hero, add a section with an `.eyebrow` rule
and an `h2` reading «Какво ремонтираме», then `.cat-grid` rendered by a `foreach` over
`$torin_categories`. Each iteration emits one `<article class="cat-card" id="...">` using the
record's `id` — the id is required on **all six regardless of publish state**, because it is
the anchor target `torin_category_href()` falls back to. Inside: the media slot calling
`torin_icon()` with the record's icon name, then the body with the `h3` anchor whose `href` is
`torin_category_href($cat)` and whose text is the record's `name`, then the symptom paragraph.
Never hand-type an href.

Escape every interpolated value on output with `htmlspecialchars($value, ENT_QUOTES)`. The
values are hardcoded today, but the same loop is what Phase 4's `sitemap.xml` will reuse, and
an unescaped attribute interpolation is the shape that becomes an injection the moment the
data source changes.

Require `categories.php` at the top of `index.html`, alongside the existing metadata
assignment, using the same relative-to-file idiom the page already uses.

Do not add a seventh item to this grid. Battery regeneration, adapter cable replacement and
free diagnostics all map to none of the six and belong elsewhere (D-15, D-26) — the grid is
exactly six.

Deploy `includes/`, `css/` and `index.html` to `public_html/new/` and run the live checks.

**Disclosure CSS.** Remove the default marker with `list-style: none` on `summary` plus the

history of breaking disclosure behaviour in WebKit, and the inner-wrapper form avoids that
entire bug class. Summary typography is `--fs-title`, `--fw-bold`, `--c-ink-deep`, minimum
height 44px, `--sp-md` padding, pointer cursor. The chevron uses `torin_icon('chevron-down')`

`--c-border` hairline, `--sp-lg` body padding, `--sp-sm` gaps between stacked items. Never
suppress the focus ring on `summary`. **Do not animate open or close** — height animation
needs `::details-content`, which is enhancement-only; the instant toggle is the contract.
