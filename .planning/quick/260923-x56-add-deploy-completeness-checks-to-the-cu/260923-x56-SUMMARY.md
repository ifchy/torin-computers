# The sweep can now tell that the server is missing files

**It passed 20/20 on a homepage showing six broken images.** That is the whole reason this exists.

## Two checks, opposite directions, neither subsuming the other

| | Asks | Catches |
|---|---|---|
| **§3b** static assets | what the **tree** contains | a file committed but never uploaded — **even when no page references it yet** |
| **§9** subresource failures | what the **pages** request | a reference to a path never committed, a typo, a stale stamp |

Both would have caught 2026-09-23. §3b is the stronger one before a cutover, because it fails
*before* the markup that needs the file ships.

The subresource half is measured **in the browser**, not by grepping markup: a regex over
`src=`/`href=` sees only what the HTML literally contains, and misses fonts and background images
referenced from CSS, anything a script requests, and every URL assembled at runtime.

`Network.loadingFailed` carries a requestId and **no URL**, so `requestWillBeSent` bookkeeping is
not optional — without the map a hard failure reports that *something* failed while being unable
to say what, which is worse than silence because it cannot be acted on.

## The lesson worth keeping: proving a check can fail is necessary, not sufficient

Both checks were deliberately proven able to fail before being trusted — a file added to `src/`
and not deployed was named with its status; real HTTP 404s came back typed Image and Stylesheet
with URLs named; a dead server came back through the `loadingFailed` path.

**Then the first real run failed 19 of 20 pages.** One repeated entry:
`net::ERR_BLOCKED_BY_CLIENT` for `gateway.umami.is/api/send` — the analytics beacon, blocked by
Brave's shields. Brave blocks trackers by default and Brave is the engine this harness drives.

Not a deploy defect, and it must never abort a cutover: the file is not ours, the server is not
involved, and the verdict would swing on the visitor's ad-blocker. **The synthetic failure was
constructed to be caught and was caught; only the real run revealed the check also caught
something it should not.** Same-origin failures are now fatal, cross-origin are reported and never
fatal — the discipline `truth-gate.js` already applies to its class-B tokens.

## What this does NOT close, stated so it is never assumed

**Content comparison.** A stale-but-present file passes both checks, so the *other* incident of
2026-09-23 — staging silently two days behind, serving a footer band the owner had removed and
theme scaffolding deleted at 04-07 — would still not be caught. **Raised as ledger 56.**

It is not trivial, which is why it is a separate entry rather than a to-do: `deploy-new.sh`
**strips comments from CSS on upload**, so stylesheets are deliberately not byte-identical to
`src/` and a naive digest comparison would report a permanent false failure on every one.

**Origin orphans.** Files on the server no longer in `src/` remain undetectable — nothing here can
list remote files. That stays the Phase 3.5 withdrawn-photographs problem and a manual FileZilla
pass at cutover.
