# Teach the sweep to notice an incomplete deploy

## Why, in one line

**The sweep passed 20/20 on a homepage showing six broken images.**

## The two instances, one root cause

| When | What happened | Sweep verdict at the time |
|---|---|---|
| 2026-09-23 morning | staging was silently **two days stale**; the footer band the owner had removed was still live on all 20 pages | 20/20 PASS |
| 2026-09-23 evening | `index.html` deployed referencing six icon files still local; **all six 404'd** | 20/20 PASS |

`deploy-new.sh` uploads and never deletes, keeps no manifest, and the origin holds no record of
what it is missing — so an incomplete deploy is invisible from both ends. And every assertion the
sweep makes (Cyrillic prose, PHP diagnostics, chat widget, console errors) is satisfied by a
partial or stale deploy. **A 404 on a referenced asset is asserted by nothing.**

For a script whose header calls it "the go/no-go instrument for the Phase 4 root cutover", *the
server is running the code you think it is* is arguably the most important thing it could assert,
and it asserts nothing of the kind.

## Two checks, deliberately from opposite directions

They catch different failures and neither subsumes the other.

**A — what the PAGE asks for.** Every subresource a real browser requests must not 4xx. Catches a
page referencing a path that was never committed at all, a typo in a filename, a stale cache-
busting stamp — anything a visitor would actually experience as broken. Implemented in the browser
because only the browser knows the true request list; a regex over `src=`/`href=` would miss
CSS-referenced fonts and background images.

**B — what the TREE contains.** Every static asset committed under `src/` must be served. Catches
a file committed but never uploaded **even when no page references it yet** — which is the
stronger check for a cutover, because it fails before the markup that needs the file ships.

Today's incident would have been caught by both. This morning's staleness would have been caught
by neither, and that is worth stating plainly: neither check compares CONTENT, so a stale-but-
present file still passes. Closing that needs a deployed-vs-committed digest comparison, which is
not in this task.

## Tasks

1. **`scripts/lib/cdp-client.js`** — `onSubresourceFailure(session, cb)`. Track `requestId → url`
   from `Network.requestWillBeSent`, because `Network.loadingFailed` carries only the id and a
   failure with no URL names nothing. Report `responseReceived` ≥ 400 and every `loadingFailed`.
   `await Network.enable` last, same contract as `onConsoleError`: unawaited, the events for a
   load already in flight are never delivered.

2. **`scripts/probes/cutover-sweep.js`** — attribute failures per page by slicing the shared
   buffer around each navigation, exactly as `consoleErrors` already does. Any failure makes that
   page **FAIL** with the URLs named. If the client lacks the export, the page is **INCONCLUSIVE
   and says so** — never an earned empty, the same discipline that the missing `onConsoleError`
   taught this project earlier today.

3. **`scripts/lib/render-digest.js`** — print whether the check ran, on every run including clean
   ones. "0 failures" means nothing unless the reader knows something was listening.

4. **`scripts/cutover-sweep.sh`** — new section: walk `src/` for `css js svg png jpg webp ico
   woff2` and assert 200 for each. Skips, each for a stated reason: `.htaccess` (deploy refuses
   it), `.user.ini`, `settings.txt.example`, `google*.html` (section 6 asserts it byte-wise),
   `vendor/phpmailer/` (deliberately 403, ledger 42), and `*.html` (section 3 covers them).

## The direction NOT covered, stated so it is not assumed

**Files on the origin that are no longer in `src/`.** `deploy-new.sh` never deletes and nothing
in this project can list remote files, so orphans are undetectable from here. That is the Phase
3.5 withdrawn-photographs problem — three unreferenced but fetchable JPEGs and four retired pages
— and it stays a manual FileZilla pass at cutover.

## Verify

A check that has never failed is a check nobody has tested. Both must be **proven able to fail**
before being trusted:

- point the asset check at a path known absent → it must report the failure and fail the run;
- give a page a reference to a missing image → the subresource check must name it;
- revert both, then run the full sweep against staging and expect 20/20 with both checks green.
