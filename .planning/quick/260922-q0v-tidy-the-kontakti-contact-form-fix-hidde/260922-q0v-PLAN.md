# Tidy the contact form

## What the owner reported

> "i'd prefer the text below input fields explaining what should be entered to be as a
> placeholder and the warning msgs not to be visible all the time even when fields are filled in
> … right now is too much information and is hard to say what is going on that page"

## What is actually on the page, measured

Seven controls carry **fourteen lines of secondary text**: 6 `.field__help`, 7 `.field__error`,
and the required-fields legend.

**The seven error lines are a bug, not a design decision.** Measured on staging with
`scripts/render-check.sh`: all 7 `.field__error` nodes have `hasHiddenAttr: true` and all 7 have
`display: flex`, `visible: true`.

`components.css:853` declares `.field__error { display: flex }`. `hidden` is enforced by the UA
stylesheet's `[hidden] { display: none }`, and **any author-origin `display` declaration beats a
UA-origin one** regardless of specificity. So the attribute has never once taken effect.

`contact-form.php` goes to real trouble to emit `hidden` conditionally on each of the seven
nodes, and documents the choice — "the `hidden` attribute on the node is what changes instead"
of toggling the `aria-describedby` id list. That intent has been silently cancelled by CSS for
as long as both files have existed.

Consequence beyond the clutter: every visitor is told «Моля, попълнете полето.» under a field
they have not touched yet, and the alert icon sits beside it. The form reads as though it is
already rejecting them before they type anything.

## Owner decisions taken (asked and answered 2026-09-22)

1. **Hints → placeholders, reassurances dropped.** `device` and `fault` carry real "what to
   enter" guidance and become placeholders. `phone` («За да ви върнем обаждане.») and `email`
   («Ще получите потвърждение…») are reassurances, not entry hints — they are removed rather
   than rewritten into fake hints, and those two fields get **no** placeholder.
2. **Errors clear as the visitor fixes them.** Nothing shows before the first submit attempt.
   After a failed submit, a flagged field re-checks on input/change so its message disappears
   when satisfied. A field that was never invalid is never flagged.
3. **Photos help shortened, kept visible.** A file input cannot carry a placeholder. Trimmed to
   «До 5 снимки, всяка до 10 MB.» — the label already says «(по избор)», so «Не е задължително»
   repeated it.

## The interaction that will break this if missed

`photo-resize.js` registers its own `submit` listener on the same form (line 130) and
**disables the submit button and relabels it** on every submit. If the validator rejects a
submit without stopping that listener, the button locks as «Изпраща се…» on a form that is not
being sent — a dead page.

`form-validate.js` must therefore be emitted **before** `photo-resize.js` (deferred scripts run
in document order, so listener order follows markup order) and call
`e.stopImmediatePropagation()` as well as `e.preventDefault()` on rejection.

Note also `photo-resize.js:114` calls `form.submit()`, which does **not** fire the submit event.
That is correct and must stay correct: validation already ran on the user-initiated submit that
started the resize, and re-running it there would be unreachable code.

## Tasks

1. **`src/css/base.css`** — add `[hidden] { display: none !important }` to the reset. Fixes all
   seven nodes at once and makes the class of defect impossible site-wide. Scoping it to
   `.field__error[hidden]` would fix this instance and leave the trap armed for the next
   component that pairs a `display` rule with a `hidden` node.

2. **`src/includes/contact-form.php`** — `device` and `fault` get `placeholder`; their
   `.field__help` nodes and the `phone`/`email` help nodes are removed; `photos-help` is
   shortened. Each control's `aria-describedby` drops the removed help ids and keeps its error
   id. Emit `js/form-validate.js` above `js/photo-resize.js`, stamped through
   `torin_asset_url()` like every other asset.

3. **`src/js/form-validate.js`** (new) — submit-time validation reading the `data-err` strings
   already on the controls. Required: device, fault, name, phone, email, consent. Email is
   checked for **emptiness only** — the server stays the one writer of the malformed-email
   message, per the existing comment, and a client-side re-implementation of
   `FILTER_VALIDATE_EMAIL` would drift from it. Toggles the `hidden` attribute and
   `aria-invalid` + `.field--invalid`, never the `aria-describedby` id list. Focuses the first
   invalid control. If the server re-rendered with errors, the form starts in the
   already-submitted state so those fields re-validate live too.

## Verify

- Rendered probe on staging: 0 of 7 error nodes visible on first load; `device`/`fault` carry
  placeholders; `phone`/`email` carry none; 2 help nodes remain (photos + legend).
- Submitting the empty form flags every required field and the button does **not** lock.
- Filling a flagged field clears its message without a second submit.
- Scripting off: the form still posts and `contact-send.php` still validates.
- `php -l` clean; selftests green.

## Out of scope

`contact-send.php` is untouched — server-side validation stays the source of truth, and its
error re-render path still drives the same markup through the same partial.
